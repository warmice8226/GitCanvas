# 이력 수정 · 복구

작업 순서 8의 Windows 프로토타입 구현 범위입니다. 메인 화면의 **이력 수정 · 복구** 탭에서 사용합니다.

## Interactive rebase

1. 기준 커밋 또는 브랜치를 입력하고 **계획 읽기**를 누릅니다. 기준은 유지하고 그 이후부터 현재 HEAD까지 편집합니다. 커밋 기록 우클릭의 **이 커밋 이후 Interactive rebase**로도 시작합니다. **첫 커밋부터**는 루트 커밋을 포함합니다.
2. 계획은 오래된 커밋부터 표시합니다. 행을 선택하고 위/아래 버튼으로 순서를 바꿉니다.
3. 동작을 선택하고, Reword는 아래 메시지 칸을 수정합니다.
4. **계획 확인 후 실행**에서 전체 계획을 확인합니다. 실행 전 HEAD와 계획 파일을 보관합니다.

| 동작 | 결과 |
|---|---|
| Pick | 커밋을 적용합니다. |
| Reword | 변경 내용은 유지하고 제목·본문을 교체합니다. |
| Edit | 해당 커밋에서 멈춥니다. 파일 수정·Stage 후 **Edit: 변경 사항에서 Amend**를 누르고 커밋을 수정한 다음 Continue합니다. 수정 없이 Continue도 가능합니다. |
| Squash | 앞 커밋에 변경과 메시지를 합칩니다. Git이 만든 합친 메시지를 유지하며, 완료 후 Amend로 다듬을 수 있습니다. |
| Fixup | 앞 커밋에 변경만 합치고 자신의 메시지는 버립니다. |
| Drop | 해당 커밋을 제외합니다. |

충돌 시 **3-way 충돌 편집기**에서 해결·Stage하고 Continue합니다. Rebase 중 Ours는 다시 쌓고 있는 쪽, Theirs는 재적용 중인 커밋입니다. Abort는 진행 중인 Rebase를 취소합니다. 앱을 다시 실행해도 Git 상태와 활성 계획을 읽어 Continue/Abort할 수 있습니다. 아직 실행하지 않은 계획 편집은 메모리에만 있으며 저장소 전환·종료 시 버릴지 확인합니다.

시작하려면 로컬 브랜치와 깨끗한 작업 트리가 필요합니다. 대상 경로와 겹치는 무시 파일, 충돌, 잠금, 변경된 HEAD·Index·작업 상태는 차단합니다. Git 작업 중 외부 도구로 같은 저장소에 쓰지 마세요. 외부 쓰기를 완전히 잠그는 기능은 없습니다.

지원 범위는 **병합 커밋이 없는 1~200개 커밋**입니다. 병합 구조 유지, 임의 exec, todo 직접 편집, Skip, 자동 강제 Push는 제공하지 않습니다. 공유한 커밋을 수정하면 원격과 이력이 갈라질 수 있습니다. 실행 후 동기화는 Fetch부터 다시 확인합니다.

## Reflog · 복구 참조

**복구 기록 읽기**는 HEAD reflog 최근 200~2,000개와 `refs/gitcanvas/*`를 모읍니다. 검색으로 좁히고 행을 선택하면 커밋 메시지·통계·패치를 조회합니다. 복구 작업 이후에는 기록을 다시 읽습니다.

| 버튼 | 결과 |
|---|---|
| 새 브랜치로 보존 | 선택 커밋에 새 로컬 브랜치를 만듭니다. 현재 브랜치와 작업 파일은 유지합니다. |
| 현재 브랜치 되돌리기 | 깨끗한 로컬 브랜치를 선택 커밋으로 `reset --keep`합니다. 실행 전 HEAD를 다시 보관하며, 무시 파일과 대상 경로가 겹치면 거부합니다. |
| Stash 목록으로 복원 | 삭제 Stash 보관 참조를 `stash store`로 목록에 복원합니다. 파일 적용은 Stash 탭에서 합니다. |
| 복구 참조 삭제 | 앱의 복구 참조만 확인 후 삭제합니다. 확인한 OID가 바뀌었으면 거부합니다. 자동 Undo가 없고 마지막 참조를 지우면 이후 GC로 객체가 사라질 수 있습니다. |

Stash 보관본은 Stash 복원 버튼을 사용합니다. 일반 브랜치/Reset 복구로 인덱스·미추적 파일까지 복원하지 않습니다. Reflog는 만료되거나 GC로 객체가 지워지면 복구할 수 없습니다. 원격 서버의 reflog는 조회하지 않습니다.

## 보관 위치

- Rebase 시작 HEAD: `refs/gitcanvas/rebase-backups/<id>`
- 브랜치 되돌리기 직전 HEAD: `refs/gitcanvas/restore-backups/<id>`
- 계획: 실제 Git 디렉터리의 `gitcanvas/rebase-plans/<id>.json`
- 진행 계획: `gitcanvas/rebase-active.json` (완료·Abort 후 제거)
- 파일 백업: `gitcanvas/worktree-backups` 및 `gitcanvas/conflict-backups`

복구 화면에서 백업 폴더를 열 수 있습니다. **파일 백업은 manifest를 확인하여 수동 복사**하며 자동 전체 복원은 제공하지 않습니다. 커밋 참조는 미커밋 파일의 백업이 아닙니다.

Windows Git 셸에서 앱 자체를 제목표시줄 없는 편집 도우미로 호출합니다. 무설치 ZIP의 DLL을 실행 파일 옆에 유지하세요. Git은 별도로 필요합니다. 조회 출력은 8 MiB로 제한됩니다.
