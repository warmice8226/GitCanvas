# GitHub 계정·저장소 연동

작업 순서 9의 gh 기반 구현입니다. 저장소를 선택하고 **Pull Requests**를 누르면 [순서 10의 PR 생성·리뷰·CI·병합](GITHUB_PULL_REQUESTS.md)을 사용할 수 있습니다.

## 시작하기

1. **GitHub** 탭에서 **GitHub 로그인**을 누릅니다. Windows 배포 ZIP에는 공식 GitHub CLI가 포함되므로 별도로 설치하거나 명령어를 입력할 필요가 없습니다.
2. 자동으로 열린 브라우저에서 로그인하고 앱에 표시된 일회용 코드를 입력해 연결을 허용합니다. 브라우저가 열리지 않으면 **인증 브라우저 열기**로 다시 시도합니다.
3. 완료하면 Git HTTPS 인증 연결 → 계정 확인 → 저장소 목록 조회를 자동으로 수행합니다. 저장소를 선택해 **선택 저장소 Clone**을 사용할 수 있습니다.
4. 다음 실행에서도 GitHub 탭을 처음 열면 저장된 계정과 저장소를 자동으로 읽습니다. 자동 복원 시에는 Git 설정을 변경하지 않습니다.

## 고급 설정

제목표시줄 없는 별도 **고급 설정** 창에 gh 실행 파일 선택·버전 확인·설치 안내, Enterprise 호스트, 인증 상태·권한·저장 위치, 계정 전환·로그아웃과 수동 Git 인증 연결을 모았습니다. 호스트에는 `github.com` 또는 Enterprise Server 도메인만 입력합니다.

**로그인 후 Git HTTPS 인증도 자동 연결**은 기본으로 켜져 있습니다. 기존 인증 도구를 유지하려면 로그인 전에 끄세요. 자동 연결은 해당 호스트의 전역 Git credential helper를 설정하므로 다른 로컬 저장소에도 적용됩니다. 연결이 실패하거나 환경 변수 토큰이 충돌하면 자동 진행을 멈추고 이유를 표시합니다. [Git 인증 연결 공식 안내](https://cli.github.com/manual/gh_auth_setup-git)

소스 빌드는 gh 경로를 고급 설정에서 지정할 수 있습니다. 직접 지정한 경로 → 앱과 같은 폴더의 `gh.exe` → PATH → Windows 기본 설치 위치 순으로 찾습니다. 배포 스크립트는 공식 gh 2.100.0 Windows ZIP의 SHA-256을 공식 체크섬과 비교하고 실행 파일 및 라이선스를 포함합니다.

압축을 푼 앱 폴더를 나중에 이동했다면 **고급 설정 → Git HTTPS 인증 연결**을 다시 실행해 Git이 사용할 로그인 도구 경로를 갱신하세요.

로그인은 gh의 해당 호스트 기본 Git 프로토콜을 HTTPS로 설정합니다. 기존 저장소의 원격 URL과 SSH 키는 바꾸지 않습니다.

앱은 토큰을 직접 입력받거나 로그·QSettings에 저장하지 않습니다. gh는 OS 자격 증명 저장소를 우선 사용하되 사용할 수 없으면 gh 설정 파일에 평문으로 저장할 수 있습니다. 계정의 **저장 위치**를 확인하세요. 로그인은 gh 기본 권한(repo/read:org/gist)을 사용하며 추가 권한을 요구하지 않습니다. [gh 로그인 공식 안내](https://cli.github.com/manual/gh_auth_login)

## 계정과 Git 인증 범위

- **인증 상태 다시 확인**은 선택 호스트의 등록 계정, 활성 여부, 인증 상태, scope, 저장 위치를 표시하고 활성 계정의 저장소까지 자동 조회합니다. JSON 명령의 종료 코드가 0이어도 계정 상태가 success가 아니면 저장소 조회를 활성화하지 않습니다. [gh 인증 상태](https://cli.github.com/manual/gh_auth_status)
- **선택 계정으로 전환**은 해당 호스트의 gh 활성 계정을 바꿉니다. 다른 프로그램에서 사용하는 gh에도 영향을 줍니다. 전환 전에 적용 범위를 확인하며 저장소 목록을 비웁니다.
- **로그아웃**은 gh의 로컬 인증 등록을 제거합니다. 서버 토큰 자체의 폐기는 GitHub 설정에서 별도로 합니다. 로컬 저장소와 커밋 작성자 설정은 유지합니다.
- Git 작성자(name/email), 원격 URL, SSH 키는 GitHub API 계정과 별개입니다. **Git HTTPS 인증 연결**은 확인 후 해당 호스트의 전역 credential helper를 gh로 설정합니다. Clone/Fetch/Push는 기존 Git 인증 체계를 사용하므로 이 연결을 설정하거나 기존 helper를 확인하세요.
- 이 화면의 gh 요청에서는 환경 변수 토큰을 제외하고 저장된 계정을 사용합니다. 환경 변수 토큰이 있는 상태에서는 Git HTTPS 인증 연결을 차단해 두 인증 범위가 달라지는 것을 안내합니다.

## 저장소 조회와 Clone

**활성 계정 저장소 조회**는 인증 사용자 REST API에서 개인 소유·협업·조직 접근 저장소를 최근 갱신 순으로 100개씩 읽습니다. **다음 100개**로 이어 읽으며 불러온 목록을 이름/소유자, 개인/조직, public/private/internal로 필터링합니다. pull/push/admin/maintain/triage는 API가 제공한 현재 저장소 권한이며 보호 브랜치 쓰기 권한을 보장하지 않습니다. [인증 사용자 저장소 API](https://docs.github.com/en/rest/repos/repos#list-repositories-for-the-authenticated-user)

호스트·계정 변경 시 목록을 초기화하고 페이지 조회 전후 활성 사용자를 재검증합니다. 다른 프로그램에서 gh 계정이 바뀌면 응답을 버립니다. 목록을 디스크에 캐시하지 않으며 접근할 수 없게 된 로컬 Workspace 폴더를 삭제하지 않습니다.

**선택 저장소 Clone**은 기존 Clone 창에 HTTPS 주소를 채웁니다. 저장할 폴더와 Clone 방식을 확인하고 실행하면 성공한 저장소를 Workspace에 등록합니다. GitHub 링크와 Clone 주소는 선택 호스트의 HTTPS 주소만 허용합니다.

## 중단·오류와 현재 한계

- API 조회는 45초, 로그인은 5분 제한이며 응답은 4 MiB까지입니다. **GitHub 요청 중단**으로 멈출 수 있습니다. 인증 쓰기는 이미 반영됐을 수 있으므로 중단 후 상태를 다시 읽으세요.
- GitHub 작업 중 다른 기능 탭과 상단 Git 작업을 잠가 계정 변경과 원격 작업이 겹치지 않게 합니다. 실행 중에는 앱 종료를 보류합니다.
- 인증 만료/401, 권한 부족/403, SSO, 저장소 없음/404, 호출 한도를 구분해 안내합니다. 호출 한도 초과 시 자동 재시도하지 않습니다.
- gh 없는 독립 Device Flow, 프로필 아바타 이미지, installation별 목록, 로컬 Clone 여부 필터, 서버의 세부 조직 정책 판별은 후속 범위입니다. 계정 전환과 API 호출 간 외부 gh 프로그램의 동시 변경을 OS 차원에서 잠그지는 않습니다.

검증: 모의 gh 실행 파일을 이용해 다중 계정, 활성 사용자 전후 확인, 페이지 조회, 토큰 정보 비노출, 환경 변수 분리, 실패·중단·gh 누락, GUI 목록 초기화와 Clone 주소 전달을 검사합니다. 브라우저 호출을 가로채 자동 열기, 로그인→Git 인증 연결→계정→저장소 순서, 자동 복원, 고급 설정 분리 및 자동 연결 해제·차단도 검사합니다. 실제 사용자 로그인 및 GitHub Enterprise/조직 SSO 서버와의 실계정 검증은 별도입니다.
