# Windows 프로토타입

## 실행

Workspace의 **앱 설정 · 진단**에서 한/영 언어(다음 실행 적용), 진단 보관·내보내기를 설정합니다. 자세한 범위는 [언어·진단·성능·배포](QUALITY_AND_DEPLOYMENT.md)를 참고하세요.

`GitCanvas-0.1.0-windows-x64.zip`을 **전체 압축 해제**하고 `GitCanvas/bin/GitCanvas.exe`를 실행합니다. 설치 관리자, Qt 및 개발 도구 설치는 필요하지 않습니다. exe 파일만 다른 곳으로 옮기지 마세요.

Windows x64용입니다. Git for Windows가 설치되어 있고 `git`이 PATH에 있어야 합니다. Workspace의 **Git 환경 · 작성자 설정**에서 Git 버전·실행 파일 경로와 작성자 설정을 확인합니다. 이름·이메일은 앱에서 Local/Global 범위로 저장할 수 있으며, 원격 인증은 기존 Git 인증 도구를 사용합니다. [설정 사용 안내](GIT_ENVIRONMENT_AND_IDENTITY.md)를 참고하세요.

## 사용 순서

1. **저장소 추가**에서 기존 로컬 Git 저장소 폴더를 선택합니다. 추가한 저장소는 Workspace 목록에 저장되며 클릭 또는 Enter로 다시 엽니다. **즐겨찾기**는 목록 상단에 고정하고, **↑ 위로 / ↓ 아래로**로 같은 그룹 안에서 순서를 바꿉니다. 목록과 순서는 앱을 다시 실행해도 유지됩니다.
2. 파일명을 클릭하면 변경 내용이 표시됩니다. 파일별 체크박스 또는 목록 위의 전체 체크로 Stage/Unstage할 파일을 고릅니다.
3. **체크한 파일 Stage ↓**를 누르면 커밋할 파일 목록에 들어갑니다. 두 목록 사이의 **체크한 파일 Unstage ↑**는 파일 내용을 유지하면서 커밋 대상에서 제외합니다.
4. **제목(필수)**과 **상세 설명(선택)**을 각각 작성하고 **커밋 만들기**를 누릅니다. 실제 커밋 메시지는 제목과 상세 설명 사이에 빈 줄을 넣어 기록합니다. 커밋은 체크 여부와 관계없이 커밋할 파일 목록의 모든 변경을 기록합니다.
5. **커밋 기록**에서 그래프와 표를 확인하고 **100개 더 보기**로 이전 기록을 추가합니다. 메시지·작성자·참조·파일·날짜 필터, 두 커밋 비교, 병합 부모 선택을 제공합니다. 변경 파일을 클릭하면 Diff를 열고, 커밋 우클릭으로 이력 작업을 실행합니다. [Diff·History 사용 안내](DIFF_AND_HISTORY.md)를 참고하세요.
6. 상단 브랜치 드롭다운에서 이름을 선택하면 즉시 전환합니다. **새 브랜치**는 현재 브랜치의 HEAD에서 생성하고 이동합니다. **이름 변경**은 현재 로컬 브랜치를, **삭제**는 현재 보고 있는 브랜치를 대상으로 합니다. 삭제 시 현재 브랜치를 제외하고 main → master → 다른 로컬 브랜치 순으로 자동 이동합니다. 이동 대상을 따로 선택하지 않습니다. 다른 브랜치가 없으면 현재 커밋을 유지하는 detached HEAD로 전환합니다. **강제 삭제**를 체크할 때마다 경고를 확인해야 합니다. **연결된 원격 브랜치도 삭제**는 upstream이 있을 때만 선택할 수 있습니다.
7. **동기화 버튼** 하나가 현재 상태에 따라 바뀝니다. 먼저 Fetch로 연결된 원격 브랜치를 확인해야 Pull/Push가 가능합니다. 원격이 앞서면 Pull, 내 커밋만 앞서면 Push, 같으면 다시 Fetch를 표시합니다. 각 클릭은 표시된 작업 하나만 실행합니다.

외부 편집기로 파일을 수정한 뒤에는 **로컬파일 새로고침**을 누릅니다. **원격 · 브랜치 연결**에서 remote와 upstream을 설정하고 상단 Fetch 후 최초 Push를 실행합니다. **새 저장소 / Clone**은 생성 성공 후 Workspace에 바로 등록합니다. [자세한 사용법](REMOTES_AND_WORKSPACE.md)을 참고하세요. 커밋 작성자·기록자 확인에 실패하면 설정창을 열며 초안을 유지합니다. 이름·이메일 저장 후 커밋 버튼을 다시 누르세요. 원격 인증 설정 오류는 Git 오류로 표시합니다.

## 이번 버전의 범위

**Git Tools → 전체 Git 명령 · 옵션 GUI**에서 설치된 Git의 옵션을 선택하고 값·순서·반복·바이너리 입출력을 설정합니다. Notes·Replace·Sparse·Submodule·LFS·서명·설정 다중 값 화면도 추가했습니다. Git HTML 설명서가 필요하며 Git for Windows에 포함된 문서로 검증했습니다. [지원 범위와 사용 방법](GIT_COMMAND_FORMS.md)을 참고하세요.

Workspace의 **SSH 원격 작업공간**에서 서버 연결 프로필·저장소·즐겨찾기를 관리하고, 원격 파일 편집·Stage/Unstage·커밋·브랜치·Fetch/Pull/Push·Diff·History를 사용할 수 있습니다. Windows OpenSSH Client와 원격 POSIX 서버의 Python 3.8 이상·Git 2.31 이상이 필요합니다. 접속 방법과 지원 범위는 [SSH 작업공간 안내](SSH_WORKSPACE.md)를 참고하세요. 실제 서버 접속 검증과 원격 고급 Git 기능 연동은 후속 작업입니다.

**Git Tools** 탭(`Ctrl+Shift+P`)에서 태그·연결 작업 트리·Bisect·점검/정리·설정·내보내기/패치·Submodule/LFS 기본 기능과 고급 명령을 사용합니다. [사용법과 전체 Git 기능 확장 방향](GIT_TOOLS_AND_COVERAGE.md)에 범위와 제한을 기록합니다.

**GitHub** 탭의 **GitHub 로그인**을 누르면 브라우저가 열리고 인증 후 Git HTTPS 연결과 저장소 조회를 자동으로 수행합니다. Windows 배포 ZIP에 로그인 도구가 포함되어 별도 gh 설치가 필요 없습니다. 계정 전환·Enterprise·gh 인증 옵션은 **고급 설정**에서 변경합니다. [로그인·저장 위치·인증 범위 안내](GITHUB_ACCOUNTS_AND_REPOSITORIES.md)를 확인하세요.

실제 로컬 저장소 조회·생성·Clone, remote·upstream·최초 Push 설정, 파일·구간·줄 단위 Stage/Unstage, 커밋·Amend·sign-off, 통합/나란히 Diff, 브랜치 조작, 검색 가능한 기록, Fetch/Pull/Push, Stash·파일 정리, 병합·3-way 충돌 해결, 선형 interactive rebase·reflog 복구를 제공합니다. GitHub 저장소를 선택한 뒤 **Pull Requests**에서 [PR 생성·리뷰·CI·병합·체크아웃](GITHUB_PULL_REQUESTS.md)을 사용할 수 있습니다. UI는 한국어·영어를 지원합니다. [이력 수정·복구 사용법](HISTORY_REWRITE_AND_RECOVERY.md)을 참고하세요.

신규 파일은 앞 8 MiB를 미리 봅니다. Diff·History 조회는 출력 8 MiB 초과 시 중단합니다. 대규모 저장소 캐시·가상화는 후속 작업입니다. **작업 상태 · 복구** 탭에서 충돌·잠금, Continue/Abort와 명령별 시간 제한을 확인합니다. 조회·Fetch·Clone은 중단할 수 있으며 쓰기는 강제 중단하지 않습니다. [중단과 복구 정책](OPERATIONS_AND_RECOVERY.md)을 참고하세요. 원격 인증은 기존 Git credential helper/SSH 설정을 사용합니다.

## 개발과 검증

MSYS2 UCRT64의 Qt 6, CMake, Ninja, GCC가 준비된 Windows에서 저장소 루트 기준:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-windows.ps1
```

필요 패키지: `mingw-w64-ucrt-x86_64-qt6-base`, `mingw-w64-ucrt-x86_64-cmake`, `mingw-w64-ucrt-x86_64-ninja`, `mingw-w64-ucrt-x86_64-gcc`.

스크립트는 빌드, 자동 테스트, Qt 및 전이 DLL 의존성 수집과 ZIP 생성을 수행합니다. 출력은 `out/GitCanvas-0.1.0-windows-x64.zip`입니다. MSYS2 의존성의 라이선스 문서는 `third-party-licenses`에 포함합니다.

GUI 통합 테스트는 임시 저장소에서 한글·공백 파일명, 신규 파일 미리보기, 첫 커밋 이전 unstage, stage와 커밋, 변경 diff, 브랜치 생성·전환을 검증합니다. 체크한 파일만 Stage하는 동작, 전체 체크와 부분 체크 상태, 제목 필수 및 제목·상세 설명의 실제 커밋 기록도 검사합니다. Git 실행 파일이 없는 경우의 오류 콜백도 검사합니다. 실제 원격 서버 인증과 push는 별도 환경에서 확인해야 합니다.

추가로 임시 bare 원격 저장소를 이용한 push/fetch/pull 검증을 통과했습니다. 개발 도구 경로를 PATH에서 제거한 상태에서도 패키지 DLL만으로 GUI 테스트를 통과했습니다.

## 업데이트와 제목표시줄 확인

기본창과 플로팅창에 배경색을 맞춘 제목표시줄을 표시합니다. Windows 10에서는 앱이 그린 제목표시줄, Windows 11 이상에서는 운영체제 제목표시줄을 사용합니다.

개발용 `build/GitCanvas.exe`와 배포용 `out/GitCanvas/bin/GitCanvas.exe`, 바탕화면 등에 복사한 실행 파일은 별개입니다. 소스 빌드만으로 기존 배포 폴더가 갱신되지는 않습니다. 업데이트할 때는 작업을 마치고 기존 앱을 종료한 뒤 새 ZIP의 `GitCanvas` 폴더를 교체하세요. 예전 바로가기가 다른 폴더의 실행 파일을 가리키지 않는지도 확인합니다. 저장소와 사용자 설정은 배포 폴더 교체로 삭제하지 않습니다.

## 동기화 버튼의 안전 규칙

- 저장소를 열거나 브랜치를 바꾼 뒤에는 Fetch가 먼저입니다. Fetch 실패 시에도 Pull/Push를 다시 잠급니다.
- 양쪽 이력이 갈라지면 `Pull 우선 · 이력 통합 필요` 버튼으로 비교·병합 화면을 엽니다. 3-way 편집기에서 충돌을 해결하고 Continue한 뒤 다시 Fetch하면 Push로 이어집니다. [고급 커밋·병합 사용 안내](ADVANCED_COMMIT_AND_MERGE.md)를 참고하세요.
- 작업 중인 파일 변경이 있으면 Pull을 차단합니다. 먼저 커밋하거나 Stash · 작업 트리 탭에서 임시 보관하세요.
- upstream 연결이 없으면 **원격 · 브랜치 연결**에서 대상을 지정합니다. detached HEAD/첫 커밋 이전에는 Pull/Push를 제공하지 않습니다. 원격에 대상 브랜치가 없으면 Fetch 후 최초 Push로 게시할 수 있습니다.
- Pull/Push 직전에 저장소 상태를 재검사합니다. 화면에서 확인한 상태가 달라지면 Fetch부터 다시 시작합니다.
- 가져오는 주소와 올리는 주소가 다르거나 Push 주소가 여러 개이면 동기화를 차단합니다.
- Pull은 fast-forward만 허용하며 자동 stash/rebase를 하지 않습니다. Push는 비교한 upstream 브랜치에만 일반 Push를 하며, 강제 Push·태그 동반 Push·submodule 자동 Push를 하지 않습니다.
- **Stash · 작업 트리** 탭에서 변경 보관·Apply/Pop·보관본 삭제·보관본 브랜치 생성, 체크 파일 변경 폐기·rm/mv·Clean 및 .gitignore 편집을 제공합니다. 파일 백업과 삭제 보관본 복구 참조를 남깁니다. [사용법과 복구 안내](STASH_AND_WORKTREE.md)를 참고하세요.
- Fetch 이후 다른 사람이 새 커밋을 올릴 수 있습니다. 서버가 Push를 거절하면 다시 Fetch하여 비교하세요.


상단은 저장소 정보 / 브랜치 조작 / 로컬파일 새로고침·동기화의 세 구역입니다. 폴더명과 현재 브랜치를 같은 구역에 표시하고 아래에는 작은 글씨로 경로를 표시합니다. 저장소 선택, 브랜치 입력·삭제와 오류 대화상자는 제목표시줄 없이 표시되며 확인 또는 취소 버튼으로 닫습니다.

각 기능 탭에는 소개가 표시되며 하위 탭 없이 같은 페이지의 구역을 사용합니다. 변경 사항은 왼쪽 파일 목록 아래에서 커밋을 작성하고 오른쪽에서 Diff를 확인합니다. **나란히 확인 / 쌓기형 확인**으로 배치를 바꾸며 통합 Diff·줄 선택도 유지합니다.

커밋 기록의 일반 검색은 메시지 전용이며 **상세 검색**에서 작성자·경로·날짜 등을 설정합니다. 날짜는 직접 입력과 달력을 지원합니다. History는 본문 전체를 사용하고 좌우 스크롤로 상세 열을 확인합니다. 커밋을 더블 클릭하면 왼쪽 파일 목록·오른쪽 Diff의 비교창이 열립니다. 충돌 파일 선택 시에는 왼쪽 Base·가운데 최종 결과·오른쪽 Merge의 별도 큰 편집창이 열립니다.

작업 로그의 **[UI]** 행은 버튼 클릭·메뉴 선택입니다. 이어서 실행된 Git 명령과 시간순으로 비교할 수 있습니다.

## 전체 파일 Stage / Unstage와 현재 브랜치 삭제

- 체크한 파일 버튼 옆의 **전체파일 Stage / 전체파일 Unstage**는 체크 상태와 관계없이 해당 목록의 모든 파일에 적용합니다. Unstage는 파일 내용을 보존합니다.
- 삭제는 현재 브랜치 확인 → 자동 결정한 위치로 전환 → 로컬 삭제 → 선택한 경우 원격 삭제 순서로 실행합니다. 전환 실패 시에는 삭제하지 않습니다.
- 현재 브랜치를 드롭다운에서 다시 선택하면 Git 전환 작업을 실행하지 않습니다. 로컬 브랜치가 하나만 남으면 삭제 버튼이 비활성화됩니다.
- 강제 삭제 체크는 기본 꺼짐이며 켤 때마다 경고가 표시됩니다. 경고에서 아니요를 누르면 체크가 해제됩니다. 강제 삭제는 로컬 브랜치에만 적용하며 원격 보호 규칙을 우회하지 않습니다.
- 원격 체크는 기본 꺼짐이며 현재 브랜치에 연결된 upstream의 remote/ref를 삭제 대상으로 표시합니다. 이는 연결 설정 존재 여부이며 실제 접속·권한·보호 규칙은 실행 결과로 확인합니다.
- 로컬 삭제 실패 시 전환된 위치에 남고 원격 삭제는 하지 않습니다. 로컬 삭제 후 원격 삭제가 실패하면 부분 성공을 안내합니다.
