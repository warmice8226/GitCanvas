# Stash · 작업 트리 정리

작업 순서 5의 Windows 프로토타입 사용 안내입니다. 저장소를 열고 **Stash · 작업 트리** 탭으로 이동합니다.

## 변경 임시 보관

- **변경 보관**: 수정 내용과 Stage 상태를 Stash에 저장하고 작업 파일을 되돌립니다. 첫 커밋이 있어야 합니다.
- **새 파일도 포함**: 미추적 파일도 보관합니다. `.gitignore` 등으로 무시한 파일은 보관하거나 삭제하지 않습니다.
- 목록을 선택하면 변경 파일 통계와 패치를 보여줍니다. 미추적 파일을 포함하며, 바이너리는 Git의 요약으로 표시합니다. 상세 출력은 8 MiB로 제한합니다.
- **Apply**: 현재 브랜치에 변경을 복원하고 보관본을 유지합니다. 체크박스로 보관 당시 Stage 상태도 복원할 수 있습니다.
- **Pop**: Stage 상태를 복원하지 않고 변경을 적용합니다. 성공한 경우에만 보관 목록에서 제거합니다.
- **선택/전체 삭제**: 작업 파일을 유지하고 보관 목록만 지웁니다. 삭제할 Stash 커밋은 먼저 `refs/gitcanvas/stash-backups/<작업 ID>/<번호>`에 보존합니다. 성공한 Pop과 보관본 브랜치 생성도 같은 복구 참조를 남깁니다.
- **보관본에서 브랜치 생성**: 보관 당시의 원래 커밋에서 새 브랜치를 만들고 Stage까지 복원합니다. 현재 작업 트리가 깨끗해야 하며 성공하면 보관 목록에서 제거합니다.

복원 충돌은 일부 파일을 변경할 수 있지만 보관본은 삭제하지 않습니다. **작업 상태 · 복구** 탭에서 충돌 파일을 확인하고 외부 편집기로 해결한 뒤 Stage하세요. Stash 충돌에는 Git의 전용 `stash --abort`가 없으므로 자동 Abort를 제공하지 않습니다. 브랜치 생성 후 복원에 실패하면 새 브랜치에 머물 수 있습니다.

Pull 전에 변경을 보관하고 상단에서 다시 Fetch한 다음 Pull하세요. 이후 Apply로 복원하면 됩니다. 자동 Stash나 자동 병합은 수행하지 않습니다.

## 작업 파일 정리

추적 파일 전체와 무시되지 않은 미추적 파일을 표시합니다. 체크한 파일에만 명령을 적용합니다. 빈 상태 표시는 변경 없는 추적 파일, `?`는 미추적 파일입니다.

| 버튼 | 영향 |
|---|---|
| 작업 파일 변경 폐기 | 작업 파일을 인덱스(Stage)의 내용으로 복원. Stage 변경은 유지 |
| Stage 포함 변경 폐기 | Stage와 작업 파일을 HEAD로 복원. 새로 Stage한 파일은 삭제되며 이름 변경은 원래 경로로 복원 |
| Clean | 체크한 미추적 일반 파일 삭제. 확인창의 파일 목록이 삭제 대상 미리보기 |
| 이동 / 이름 변경 | 추적 파일 하나에 `git mv` 실행. 새 상대 경로를 지정하며 기존 대상은 덮어쓰지 않음 |
| 추적 파일 삭제 | `git rm`으로 파일 삭제를 Stage. 수정된 파일은 Git의 기본 보호에 따라 거부하며 강제 삭제는 제공하지 않음 |

첫 커밋 이전에는 HEAD로 복원할 수 없습니다. 폴더, 심볼릭 링크, 중첩 저장소, 서브모듈 자체에 대한 정리는 지원하지 않습니다. Clean은 무시된 파일을 포함하지 않으며 `-d`, `-x`, `-ff`를 사용하지 않습니다. 파일명은 리터럴 경로로 전달하므로 `[]` 등의 문자가 다른 파일 선택으로 확장되지 않습니다.

## .gitignore 편집

최상위 `.gitignore`를 UTF-8 텍스트로 편집하고 저장합니다. 예를 들어 `build/`는 빌드 폴더, `*.log`는 로그 파일을 제외합니다. 이미 추적 중인 파일은 자동으로 추적 해제하지 않습니다. 저장한 규칙 파일은 변경 사항 탭에서 Stage·커밋할 수 있습니다.

1 MiB를 초과하거나 UTF-8이 아니거나 심볼릭 링크인 기존 파일은 편집을 차단합니다. 편집 초안은 앱 실행 중 저장소별로 유지합니다. 디스크 파일이나 저장소 상태가 바뀌면 오래된 초안 저장을 거부합니다. 이때 목록 새로고침으로 초안을 버리고 디스크에서 다시 읽을 수 있습니다. 앱을 종료하기 전에는 저장하세요.

## 확인과 복구

모든 쓰기는 영향 확인창에서 승인한 뒤 실행합니다. 저장소·HEAD·인덱스·작업 상태·Stash 목록 및 파일 내용 지문을 재확인하므로 확인 이후 변경이 감지되면 거부합니다. 진행 중인 병합/리베이스, 미해결 충돌, Git 잠금이 있으면 쓰기를 차단합니다. 읽기/상세 조회는 중단할 수 있지만 로컬 쓰기는 강제 종료하지 않습니다.

파일 정리와 ignore 저장 전, 실제 Git 디렉터리의 `gitcanvas/worktree-backups/<작업 ID>/`에 선택 파일 원본과 인덱스를 복사합니다. `manifest.json`에는 원래 상대 경로와 존재 여부, 번호별 백업 파일, 파일 권한을 기록합니다. 이름 변경 폐기는 이전 경로도 포함합니다. 백업 실패 시 원본은 변경하지 않습니다. 백업 후 상태도 재확인합니다.

결과 메시지에서 복구 폴더/참조를 복사할 수 있습니다. 파일은 `manifest.json`의 경로를 확인해 번호별 `.bin` 내용을 수동으로 복사해 복구합니다. 선택한 파일의 Stage 내용은 `staged/<원래 상대 경로>`에도 별도로 내보냅니다(Git의 checkout 변환 적용). 백업 `index`는 원래 Git 객체 데이터베이스와 함께 사용하는 추가 조회 자료입니다. **현재 인덱스에 무조건 덮어쓰지 마세요.** 삭제한 Stash는 `<작업 ID>/<번호>`까지 포함한 복구 참조를 `git stash apply <복구 참조>` 또는 `git stash store <복구 참조>`로 다시 사용할 수 있습니다.

복구 자료는 자동 삭제하지 않습니다. **이력 수정 · 복구** 탭에서 삭제 Stash를 목록에 복원하거나 파일 백업 폴더를 열 수 있습니다. 파일 백업은 manifest를 확인해 수동 복사합니다. 쓰기 실패는 원자적 롤백을 뜻하지 않습니다. 결과와 복구 위치를 확인하고 새로고침하세요. 다른 Git 프로그램이나 편집기의 동시 쓰기를 완전히 잠그지는 못합니다. 파일 내용 확인과 백업은 파일 크기에 따라 시간이 걸리며 대규모 저장소 성능은 별도 검증 대상입니다.

## 검증

임시 저장소에서 Stage/작업 파일/미추적/무시 파일의 보존, Apply의 인덱스 복원, Pop 성공과 충돌, drop/clear 복구 참조, 보관본 브랜치, 오래된 확인 거부, 파일 백업, 이름 변경 폐기, rm 보호, 리터럴 Clean, ignore 저장을 검증합니다. GUI 테스트는 메인 창의 탭에서 저장·상세·복원과 제목표시줄 없는 확인창을 검사합니다.
