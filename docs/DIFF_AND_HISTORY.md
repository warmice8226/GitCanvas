# Diff와 History 사용 안내

기준일: 2026-09-11. Windows 프로토타입에 연결된 기능을 설명합니다.

## 변경 내용을 확인하고 일부만 Stage하기

1. 변경 사항 탭에서 파일명을 클릭합니다. 체크박스는 파일 단위 작업 대상을 선택하는 용도입니다.
2. Diff 보기 목록에서 **통합 Diff**, **나란히 확인**, **쌓기형 확인**을 선택합니다. 나란히/쌓기형은 이전·이후 내용과 줄 번호를 가로/세로로 표시하며 두 화면을 함께 스크롤합니다. 하위 탭은 없습니다.
3. 아래 목록에서 변경 구간(hunk)을 선택하고 **선택 구간 Stage**를 누릅니다. 커밋할 파일 목록에서는 **선택 구간 Unstage**로 해당 구간만 제외할 수 있습니다.
4. **줄 선택** 보기의 체크박스로 임의의 추가·삭제 줄을 Stage/Unstage합니다. 교체는 삭제 줄과 추가 줄을 각각 선택합니다. [고급 기능 안내](ADVANCED_COMMIT_AND_MERGE.md)를 참고하세요.

파일 목록의 기본 높이를 줄이고 새 커밋 제목·상세 설명·옵션·실행 버튼을 커밋할 파일 아래에 배치했습니다. 오른쪽은 Diff 전용입니다. 위쪽 **파일 목록 / 변경 내용 배치**는 전체 영역을 나란히/쌓기형으로 전환하며, 재실행 후에도 선택을 유지합니다.

부분 작업은 UTF-8 일반 텍스트의 수정과 신규·삭제 파일에 제공됩니다. 신규·삭제는 줄 선택을 사용하고 파일 모드 변경·바이너리는 파일 단위로 처리합니다. 실행 직전에 원본 diff를 비교하고 `git apply --cached --check`를 거칩니다. 파일 또는 Index가 바뀌면 다시 읽어야 합니다. Unstage는 작업 파일을 변경하지 않습니다.

인코딩 목록은 UTF-8, UTF-16LE/BE, 시스템 인코딩, Latin-1을 제공합니다. 화면 해석만 바꾸며 원본 파일과 적용할 패치의 바이트는 변환하지 않습니다. Git이 바이너리로 판단한 파일을 강제로 텍스트 diff로 바꾸지는 않습니다.

Diff 조회 출력은 8 MiB를 넘으면 중단하고 범위를 줄이도록 안내합니다. 신규 파일 미리보기는 앞 8 MiB까지만 읽습니다. 대형 파일의 전체 편집·가상화 기능은 아닙니다.

## 커밋과 파일 이력 확인

- **100개 더 보기**로 이전 기록을 추가합니다. 조회 조건을 적용할 때는 처음 100개부터 다시 표시합니다.
- 일반 검색은 커밋 메시지만 검색합니다. **상세 검색** 창에서 작성자·브랜치/태그/커밋 ID·파일 경로·날짜를 설정합니다. 메시지·작성자는 대소문자를 구분하지 않는 문자열 검색이며, 화면에 이미 표시된 기록 밖의 이력도 조회합니다.
- 날짜는 YYYY-MM-DD 직접 입력과 **달력** 선택을 모두 제공합니다. 상세 검색의 **초기화**는 상세 조건을 비우며 **적용**으로 조회합니다. **취소**는 창을 열기 전 조건을 복원합니다. 일반 메시지 검색어는 유지합니다.
- 브랜치 입력을 비우면 모든 참조의 이력을 조회합니다. 파일 경로는 저장소 기준의 단일 파일 경로이며 Git의 이름 변경 추적을 사용합니다. 날짜는 로컬 시간의 시작일 00:00:00부터 종료일 23:59:59까지이며 Git의 커밋 시각 기준입니다.
- 일부 커밋을 생략하는 검색에서는 잘못된 부모 연결을 보여주지 않도록 그래프 열을 숨깁니다. 확대/축소는 그래프와 표의 행 크기를 조절합니다.
- History는 탭의 본문 전체를 사용합니다. 그래프·커밋 메시지·브랜치/태그·작성자·날짜를 먼저 표시하고, 오른쪽 열에 상세 설명·커밋 ID·이메일·부모·기록 시각을 둡니다. 가로 스크롤과 열 너비 조절을 지원하며 메시지에 마우스를 올려 본문도 확인합니다.
- 행을 **더블 클릭**하면 제목표시줄 없는 큰 비교창이 열립니다. 왼쪽은 커밋 정보·부모 선택·변경 파일, 오른쪽은 같은 Diff 보기입니다. 변경 파일을 클릭하면 해당 커밋의 Diff가 열립니다. 병합 커밋은 비교할 부모를 선택하며 첫 커밋은 빈 트리와 비교합니다.
- 커밋 상세는 조회 전용으로 통합 Diff·나란히·쌓기형만 제공합니다. 사용하지 않는 줄 선택은 제거했으며 변경 사항 화면의 줄 선택 Stage/Unstage는 유지합니다.
- 커밋을 선택하고 **선택 커밋을 비교 기준으로**를 누른 다음 다른 커밋을 선택하면 `기준 → 선택` 방향의 변경 파일과 Diff를 표시합니다. **비교 해제**로 부모 비교로 돌아갑니다.
- 변경 파일을 우클릭하면 해당 파일의 이력 또는 선택 커밋 시점의 줄별 작성자(Blame)를 엽니다. 삭제된 파일처럼 선택 커밋에 경로가 없으면 Git 오류를 표시합니다.

추가 로딩은 표시 한도를 100개씩 늘려 앞부분을 다시 조회합니다. 캐시나 가상 스크롤은 아직 없으며, 이력·변경 파일·Blame 조회도 출력 제한을 적용합니다. 아주 큰 저장소에서는 필터로 범위를 줄여 사용합니다.

## 커밋 우클릭 작업

커밋 ID 복사, 비교 기준 지정, 해당 커밋으로 이동(detached HEAD), 해당 지점의 브랜치/로컬 태그 생성, 해당 커밋을 가리키는 로컬 브랜치로 전환을 제공합니다.

이력 변경 메뉴에서는 선택 커밋을 현재 브랜치에 Merge, 현재 브랜치를 선택 커밋 위로 Rebase, 선택 커밋의 Revert/Cherry-pick, 선택 위치로 Soft/Mixed/Hard Reset을 실행할 수 있습니다. 병합 커밋의 Revert/Cherry-pick은 기준 부모를 선택합니다. 자동 Push는 하지 않습니다.

이력 변경은 확인창을 거치며 미커밋 변경(미추적 파일 포함), detached HEAD 또는 진행 중인 병합·rebase 등의 작업이 있으면 막습니다. 실행 전 현재 HEAD를 `refs/gitcanvas/backups/<고유 ID>`에 저장하고 결과창에 복구 참조를 안내합니다. 이 참조는 커밋을 보존하며, 작업 디렉터리 전체나 무시된 파일을 백업하는 기능은 아닙니다.

실패 시 Git 오류와 복구 참조를 표시하고 Abort를 선택할 수 있습니다. Abort하지 않으면 상태를 유지합니다. **병합 · 충돌 해결**의 3-way 편집기에서 해결·Stage한 뒤 Continue할 수 있고, **작업 상태 · 복구**에서도 Continue/Abort를 제공합니다. Interactive rebase와 복구 참조 관리는 **이력 수정 · 복구** 탭에서 제공합니다. [이력 복구 안내](HISTORY_REWRITE_AND_RECOVERY.md)를 참고하세요.

## 검증 범위

임시 저장소 통합 테스트에서 두 구간 중 하나의 Stage/Unstage, 오래된 diff 적용 차단, 출력 제한, UTF-16 미리보기, 100개 이후 로딩과 전체 이력 검색, 작성자·경로 필터, 두 커밋 비교, 병합 부모 변경, 커밋 파일 Diff, Soft Reset 및 복구 참조 생성을 확인했습니다. 모든 이력 변경 명령의 충돌 조합이나 대규모 저장소 성능을 검증한 것은 아닙니다.
