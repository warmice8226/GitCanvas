# Git Tools와 전체 Git 기능 확장 방향

작업 순서 13의 기능을 메인 화면 **Git Tools** 탭에 추가했습니다. `Ctrl+Shift+P`로 열어 기능을 검색할 수 있습니다.

**전체 Git 명령 · 옵션 GUI**에서 설치된 Git 설명서를 바탕으로 옵션·값·반복·순서를 선택하고, 바이너리 파일 입출력을 연결할 수 있습니다. Notes·Replace·Sparse·Submodule·설정 다중 값·LFS·서명 등의 기능별 화면도 확장했습니다. [새 GUI 사용법과 전체 구현까지 남은 범위](GIT_COMMAND_FORMS.md)를 참고하세요.

목표는 Git의 로컬 기능 전체를 앱에서 접근할 수 있게 하는 것입니다. 이번 구현은 아래 기능별 입력 화면과 고급 명령 실행 기반을 제공합니다. **Git의 모든 명령·옵션에 전용 GUI와 개별 안전 검증을 완성했다는 뜻은 아닙니다.** 설치된 Git 버전과 확장 프로그램에 따라 제공 범위가 달라집니다.

## 사용하는 순서

1. 기능을 검색·선택하고 이름·참조·경로 등 필요한 값을 입력합니다. 파일/폴더는 찾기 버튼 또는 직접 입력을 사용합니다. 새 출력은 존재하지 않는 경로를 지정합니다.
2. **조회 / 실행 미리보기**를 누릅니다. 조회 기능은 결과를 표시합니다. 변경 기능은 저장소·영향 설명·정확한 인자 배열을 표시합니다.
3. 내용을 확인하고 **확인 후 실행**을 누릅니다. 고급 명령에는 영향 확인 체크도 필요합니다.
4. 결과와 오류를 확인합니다. 변경 이후 로컬 상태를 갱신하며 일반 동기화는 다시 Fetch부터 확인합니다.

실행 미리보기 이후 HEAD·참조·설정·Index·작업 상태·작업 트리 등록이 바뀌면 다시 미리보기해야 합니다. 입력 패치/Bundle의 내용도 비교합니다. 입력 파일은 128 MiB 이하, 조회 출력과 표준 입력 텍스트는 8 MiB 이하를 지원합니다. 경로와 인자에 공백이 있어도 따옴표로 감싸지 않습니다.

## 기능별 화면

| 기능군 | 제공 기능 | 보호와 제한 |
|---|---|---|
| 태그 | 목록 표, 가벼운/주석 태그 생성, 로컬 삭제, 원격 조회·게시·삭제 | 이름 덮어쓰기 없음. 원격 쓰기는 미리보기에서 Fetch 후 비교하며, 게시 시 대상 부재·삭제 시 예상 OID를 lease로 검사합니다. 로컬 삭제는 예상 OID로 삭제합니다. |
| 연결 작업 트리 | 목록 표·Workspace에서 열기, 새/기존 브랜치 폴더 생성, 이동·제거, 잠금·해제, 오래된 등록 정리 | 현재 폴더는 이동·제거 거부. 제거에 force를 사용하지 않아 변경·미추적 파일·잠금을 Git이 보호합니다. 새 대상 폴더를 사용합니다. 등록 정리는 3개월 만료 기준입니다. |
| Bisect | 시작, 검사 대상 변경 조회, 정상·문제·검사 불가 판단, 판단 로그, 종료 | `--no-checkout`으로 작업 파일을 유지합니다. 실제 판단 대상은 `BISECT_HEAD`이며, 현재 작업 파일이 후보로 바뀐 것으로 오해하지 않아야 합니다. |
| 점검·정리 | 객체 크기, fsck, gc, repack, maintenance 작업 선택 | 정리는 쓰기로 취급하여 강제 중단하지 않습니다. Git 설정의 만료 정책이 적용되며 `prune=now`·백그라운드 등록을 자동 지정하지 않습니다. |
| 설정 | 범위·출처 조회, System/Global/Local/Worktree 값 저장·키 제거 | 동일 키의 여러 값은 교체/제거됩니다. System은 권한이 필요할 수 있습니다. Worktree는 `extensions.worktreeConfig=true`를 먼저 설정해야 하며 Local로 조용히 대체하지 않습니다. |
| 내보내기 | ZIP archive, format-patch, 모든 참조의 bundle 생성 | 기존 출력 경로를 거부합니다. 미커밋 파일·Git 설정·LFS 객체의 전체 백업은 아닙니다. |
| 가져오기·패치 | Bundle 검증·FETCH_HEAD로 가져오기, 패치 check·Index 적용, AM 커밋 생성 | 깨끗한 파일 상태, 입력 파일 해시 비교, apply --check를 사용합니다. AM 충돌은 기존 3-way 편집·작업 상태의 Continue/Abort로 연결합니다. |
| Submodule | 재귀 상태, 초기화·기록된 커밋으로 갱신, URL 동기화 | 강제 옵션 없음. 네트워크·기존 Git 인증과 프로토콜 정책을 따릅니다. |
| Git LFS | 설치 확인·상태, 패턴 등록/해제, 현재 파일 받기 | LFS는 별도로 설치해야 합니다. 패턴 편집은 .gitattributes 변경이며 직접 검토·Stage·커밋합니다. 과거 이력 변환은 하지 않습니다. |

파일별 Blame·커밋 비교·이력 변경은 기존 **커밋 기록** 화면을 계속 사용합니다. 새로운 기능군이 기존 기능을 대체하지는 않습니다.

### Bisect의 파일 검사

현재 GUI의 Bisect는 후보 커밋을 계산하고 변경 내용을 보는 방식입니다. 빌드·실행 검사가 필요하면 `BISECT_HEAD`를 ZIP으로 내보내거나 별도 연결 작업 트리를 만들어 검사한 뒤 정상/문제 판단을 기록합니다. 원본 폴더의 자동 체크아웃과 자동 테스트 명령 실행은 후속 전용 기능입니다. 외부에서 시작한 일반 Bisect의 Reset은 Git 규칙에 따라 시작 위치로 돌아갈 수 있으므로 먼저 진행 중인 파일 변경을 보관하세요.

### 복구 범위

쓰기 직전에 가능한 경우 `refs/gitcanvas/tool-backups/<id>`로 HEAD를 보관합니다. 태그 삭제는 원래 태그 객체를 보관합니다. 이 참조는 이력 수정·복구 화면 또는 Git Tools에서 조회할 수 있습니다.

삭제한 태그는 **가벼운 태그 생성**에서 원래 이름과 보관 참조를 지정해 복원할 수 있습니다. 보관 대상이 주석 태그 객체면 해당 객체를 다시 가리킵니다. 기존 이름은 덮어쓰지 않습니다. 주석 태그 객체 자체를 브랜치 복구용 커밋 OID로 취급하지 마세요.

HEAD 참조는 **설정 값·미커밋 파일·제거한 작업 폴더·원격 전체의 백업이 아닙니다.** 설정, 저장소 정리, 고급 명령은 자동 Undo를 제공하지 않습니다. 미리보기와 실행 사이의 외부 쓰기를 완전히 잠그지 않으므로 다른 Git 도구와 동시에 수정하지 마세요. 실패한 명령도 일부 변경을 남길 수 있습니다.

## 고급 실행

**설치된 Git 명령 탐색**은 내장 명령·확장 명령·별칭 이름을 나열합니다. 결과에서 검색할 수 있습니다. **인자 단위 Git 실행**은 현재 설치된 내장 명령과 `lfs`를 실행하며, 별칭·그 외 확장 명령의 실행은 외부 터미널에 남깁니다.

입력 예시:

```text
log
--oneline
--all
--max-count=30
```

각 줄이 하나의 인자입니다. `git` 자체, 셸 파이프·리다이렉션·따옴표 문법은 쓰지 않습니다. `$()`·`;` 등은 문자열 그대로 전달됩니다. 표준 입력 칸은 UTF-8 텍스트를 그대로 전달한 뒤 닫습니다. 예를 들어 `hash-object`, `-w`, `--stdin`을 각 줄에 입력하고 표준 입력에 내용을 넣으면 객체를 저장할 수 있습니다.

- `log --output`처럼 조회 명령도 파일에 쓸 수 있어 고급 실행은 항상 쓰기로 처리합니다. 사용자 확인과 상태 검사를 거치며 강제 중단하지 않습니다.
- 새 기능은 먼저 여기서 지원 Git 버전·옵션·결과를 확인하고 전용 입력 화면으로 옮기는 방향입니다. 고급 실행이 옵션별 검증과 영향 분석을 대신하지는 않습니다.
- 첫 인자는 하위 명령이어야 합니다. 전역 `-C`, `--git-dir`, `-c`를 앞에 붙여 실행 문맥을 바꾸지 않습니다. 설정 범위 변경은 설정 화면에서 명시합니다.
- Push/Pull은 기존 동기화 화면을 사용합니다. 원격 태그 쓰기는 전용 기능을 사용합니다. 서버·credential·Git GUI 실행 명령과 대화형 편집은 이 화면에서 실행하지 않습니다.
- 편집기가 필요한 명령은 외부 편집기를 조용히 실행하는 대신 실패하게 합니다. 메시지 옵션을 명시하거나 기존 커밋·Rebase GUI를 사용합니다.
- Git hook이나 `submodule foreach` 같은 Git 기능 자체가 실행하는 외부 명령까지 격리하는 보안 샌드박스는 아닙니다.
- 인자·표준 입력은 설정에 자동 저장하지 않으며 고급 쓰기 명령 로그의 인자는 가립니다. 결과에는 설정 값이나 Git 출력이 포함되므로 공유 전에 확인합니다.
- 바이너리 출력은 화면에서 텍스트로 표시됩니다. 바이너리 결과는 내보내기 기능 또는 해당 Git 명령의 출력 파일 옵션을 사용합니다.

## 전체 기능 지원으로 확장하는 기준

기능 정의(`GitTool`)에 이름·설명·입력 항목·조회/쓰기·작업 트리 요구 조건을 등록하고, 인자 변환·미리보기·실행·테스트·문서를 한 묶음으로 추가합니다. 명령 이름만 실행할 수 있는 상태와 모든 옵션을 GUI로 검증하는 상태를 구분합니다.

| 다음 단계 | 우선순위 | 완료 기준 |
|---|---|---|
| 설정·태그 고급 옵션 | P1 · 확장 | 다중 값 조회·추가·정확한 값 제거, 서명 태그·키 입력 구현. 값 원복 UI·키 선택기·보호 태그 정책은 후속 |
| Submodule 전용 관리 | P1 · 확장 | 추가·deinit·URL/추적 브랜치 변경·하위 파일 보호 구현. 경로 이동·하위 저장소별 충돌 복구는 후속 |
| Bisect 실행 검사 | P1 | 후보 전환 전 미커밋·무시 파일 보호, 테스트 명령·종료 코드·중단 및 재개 |
| LFS 전용 관리 | P2 · 확장 | 환경·파일·잠금·lock/unlock·fetch/push·prune 미리보기·migrate 분석 구현. 실제 정리/이력 변환·백업 흐름과 서버 검증은 후속 |
| sparse-checkout·worktree 고급 | P2 · 확장 | Cone 폴더 선택·추가·재적용·해제, repair·분리 HEAD 구현. 폴더 트리 선택·force 사유·복수 작업 트리 조율은 후속 |
| Git 명령 커버리지 | P2 · 확장 | 설치 버전 HTML 기반 옵션 폼·명령별 옵션 수/미해석 항목 보고 구현. 옵션별 상호 제약·최소 버전·실패/복구 검증은 후속 |
| Plumbing·확장 프로그램 | P3 · 확장 | 구조화 인자·8 MiB 바이너리 파일 입력/출력 구현. 대형 스트리밍·확장별 신뢰·권한·프로토콜 정책은 후속 |
| 공통 명령·단축키 | P2 | 기존 화면도 공통 명령 레지스트리에 연결하고 단축키를 사용자 지정 |

서버 운영용 Git 프로세스, 셸/대화형 터미널, 임의 별칭·외부 확장의 모든 동작까지 현재 데스크톱 GUI가 대신하는 것은 아닙니다. 필요성이 확인된 항목은 위 커버리지 목록에 추가하고 별도 실행 정책을 정의합니다.

## 검증

임시 로컬·bare 저장소에서 태그 게시/삭제와 서버 변경 경합, 주석 태그 보존, worktree 생성/이동/잠금/제거·미추적 파일 보호, 고급 인자의 문자 보존·상태 변경 거부·쓰기 중단 정책, Bisect no-checkout, ZIP/Bundle/패치, fsck/repack/gc/maintenance를 검사합니다. 실제 인증 서버·LFS 대용량 전송·Submodule 인증·시스템 설정 변경과 대규모 저장소는 별도 검증 범위입니다.
