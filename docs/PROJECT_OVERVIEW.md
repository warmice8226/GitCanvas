# 프로젝트 개요와 기술 선택



## 목표

GitCanvas는 Windows·macOS·Linux를 대상으로 하는 오픈소스 Git GUI입니다. GUI가 시스템 Git CLI를 대신 실행하며 파일 상태, diff, 커밋 그래프와 고급 Git 작업을 제공합니다. 사용자는 운영체제에 맞는 무설치 파일을 내려받아 실행합니다. Windows 실행은 로컬에서 검증하며 Mac/Linux 실환경 검증은 별도 CI와 대상 기기에서 수행해야 합니다.

핵심 제품 원칙은 다음과 같습니다.

- Git 작업은 가능한 한 전용 GUI로 제공하고 실제 동작은 시스템 Git 실행 파일과 인자 호출로 수행한다.
- commit, branch, remote 작업을 넘어 tag, stash, worktree, submodule, reflog, bisect, 설정과 고급 이력 변경까지 단계적으로 범위를 확장한다.
- 전용 화면이 아직 없는 Git 명령도 인자 검증, 실행 전 미리보기와 위험 작업 확인을 제공하는 고급 실행 화면에서 사용할 수 있게 한다.
- 한국어와 영어를 최초 지원 언어로 제공한다.
- 모든 기능에는 이름만이 아니라 용도, 예상 결과와 위험도를 알려주는 짧은 설명을 제공한다.
- Git History를 상호작용 가능한 그래프로 표현해 commit 선택과 컨텍스트 메뉴에서 이동, 비교 및 이력 작업을 시작할 수 있게 한다.
- clone은 전체 이력을 받는 방식을 기본으로 하고 shallow/partial clone을 명시적인 선택 옵션으로 제공한다.

## 선택한 기술

- 언어: C++20
- GUI: Qt 6 Widgets
- Git 연동: 시스템 Git CLI
- 빌드: CMake와 Ninja
- 패키징: Windows ZIP, macOS 앱 ZIP, Linux AppImage와 Qt 배포 API
- 프로젝트 라이선스: GPL-3.0-only

## C++과 Qt를 선택한 이유

- 대량 텍스트와 파일 정보를 처리하기에 적합합니다.
- Qt에는 창, 팝업, 툴팁, 트리, 테이블, 드래그 앤 드롭과 커스텀 그래픽 기능이 있습니다.
- Windows와 Linux에서 같은 코드의 대부분을 사용할 수 있습니다.
- 가비지 컬렉션 중단 없이 객체 수명과 메모리 사용을 제어할 수 있습니다.
- Qt의 비동기 프로세스 API로 Git 실행 중에도 UI가 멈추지 않게 만들 수 있습니다.

## 순수 C를 선택하지 않은 이유

C와 C++의 실행 성능 차이가 자동으로 발생하는 것은 아닙니다. 이 프로젝트에서는 순수 C가 더 빠르다는 보장이 없고, 객체 수명, GUI 상태와 비동기 작업을 직접 관리할 코드만 늘어날 가능성이 큽니다. Qt도 C++ 프레임워크이므로 C++이 자연스러운 선택입니다.

## 현재 범위

- 저장소 선택과 마지막 저장소 기억
- 변경 파일과 staged 파일 표시
- 여러 파일 stage/unstage
- 커밋 메시지 작성 및 커밋
- Git 명령 비동기 실행과 오류 표시

## 향후 후보 기능

- 파일 diff 뷰어
- 커밋 히스토리와 브랜치 그래프
- branch 생성, 전환 및 삭제
- fetch, pull, push
- stash 관리
- merge 및 rebase 보조 화면
- GitHub Pull Request 생성, 조회, 리뷰와 병합
- 작업 취소와 진행률 표시

## Windows 프로토타입 추가 범위

변경 diff, 최근 100개 커밋의 GUI 그래프와 목록, 로컬 브랜치 생성·전환과 fetch/pull/push를 구현했습니다. 무설치 실행과 검증 방법은 [Windows 프로토타입 안내](WINDOWS_PROTOTYPE.md)를 참고하세요. 위 향후 후보 중 이 기능들의 초기 형태는 제공되며, 고급 옵션과 상호작용 그래프는 후속 대상입니다.
