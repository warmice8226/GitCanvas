# GitCanvas 필수 기능 명세

이 문서는 README의 개발 목표와 현재 기능, 그리고 대화에서 확정한 요구사항을 한곳에 합친 제품 기준 문서입니다. GitCanvas가 정식 버전으로 공개되기 전에 제공해야 할 기능을 정의하며, 사용자 화면, Git/`gh`/API 연결, 안전장치와 완료 조건을 함께 기록합니다.

## 프로젝트 목표와 현재 상태

### 개발 목표

- Git CLI가 제공하는 로컬 기능 전체를 GUI에서 버튼, 메뉴와 키보드 단축키로 실행할 수 있게 한다.
- 전체 지원은 기능별 입력 화면과 고급 실행 기반을 함께 확장하되, 명령 실행 가능 상태와 옵션별 GUI·검증 완료 상태를 구분한다. 현재 커버리지와 다음 순서는 [Git Tools 확장 방향](GIT_TOOLS_AND_COVERAGE.md)에 기록한다.
- GUI 조작은 내부적으로 시스템 `git` 실행 파일과 안전하게 분리된 인자 목록으로 변환한다.
- IntelliJ 계열 IDE처럼 base/ours/theirs와 결과를 비교하며 해결하는 자체 3-way merge 인터페이스를 제공한다.
- GitHub 계정을 여러 개 등록하고 자유롭게 전환하며, 활성 계정과 접근 권한에 맞는 저장소만 표시한다.
- 로컬 및 SSH 원격 컴퓨터의 Git 저장소를 같은 GUI에서 관리하고 컴퓨터·OS 사용자·Git 작성자·GitHub 계정 scope를 분리한다.
- GitHub Pull Request의 생성, 조회, 리뷰 요청, 댓글, 승인, 변경 요청, CI 확인과 병합을 지원한다.
- Git History를 조작 가능한 그래프로 제공한다.
- 한국어와 영어, 기능 설명, 오류 원인 추적 및 복구 안내를 제공한다.
- Windows와 Ubuntu에서 설치형 및 무설치형으로 배포한다. macOS는 별도 빌드·서명·테스트가 준비된 이후 지원 범위에 추가한다.

### 현재 구현된 기능

- Git 저장소 선택 및 마지막 저장소 기억
- 변경 파일과 staged 파일 조회
- 여러 파일 stage/unstage
- 커밋 메시지 작성 및 커밋
- 모든 Git 명령 비동기 실행

Windows 프로토타입에는 diff 미리보기, 최근 100개 커밋의 GUI 그래프와 목록, 로컬 브랜치 생성·전환과 fetch/pull/push도 구현되어 있습니다. 아래의 상세 명세 전체가 완료된 것은 아니며, 실행 방법과 제한은 `WINDOWS_PROTOTYPE.md`를 참고하세요.

## 제품 범위와 공통 UX 원칙

- 최종 기능 범위는 Git CLI가 제공하는 모든 기능이다. 정식 화면은 사용 빈도와 위험도에 따라 단계적으로 추가한다.
- GUI는 셸 명령 문자열을 실행하지 않고 Git 실행 파일과 인자를 분리해 호출한다. 사용자는 일반 작업에서 Git Bash나 터미널을 열 필요가 없어야 한다.
- 전용 화면이 구현되지 않은 기능은 고급 명령 실행 화면에서 제공하되, 저장소 내부에서만 실행하고 명령 미리보기, 인자 검증, 위험 작업 추가 확인과 실행 결과 기록을 제공한다.
- 각 버튼, 메뉴, 옵션에는 한두 문장의 설명을 툴팁 또는 화면 내 도움말로 제공한다. 설명에는 기능의 목적과 파일·staging·branch·history에 미치는 영향을 포함한다.
- 모든 Git 작업은 실행될 명령을 사용자가 확인할 수 있게 한다. 기본 화면은 안전한 권장값을 사용하고 `자세히`에서 체크박스, 드롭다운과 입력 필드로 고급 옵션을 조합한다.
- 사용자용 UI와 앱의 오류 설명은 한국어와 영어를 지원한다. 진단을 위해 Git 원문 출력은 번역문과 구분해 함께 제공한다.
- 현재 Git 버전에서 지원하지 않는 기능은 비활성화하고 필요한 최소 버전과 대안을 설명한다.

## 우선순위

| 단계 | 목표 | 포함 기능 |
|---|---|---|
| 1단계 | 로컬 저장소 작업 완성 | commit, branch, history, diff, 로컬 저장소 등록 |
| 2단계 | 원격 저장소 작업 | fetch, pull, push, clone, 원격 저장소 목록 |
| 3단계 | 계정과 GitHub 연동 | Git 작성자 설정, GitHub 로그인, 계정 전환, GitHub 저장소·Pull Request 조회 |
| 4단계 | 고급 이력 변경 | merge, reset, rebase, 충돌 해결 |
| 5단계 | 제품 완성도 | 다국어, 진단 로그, 복구 안내, 대규모 저장소 최적화 |

reset과 rebase는 기본 Git 기능이지만 이력을 잃거나 원격 협업에 영향을 줄 수 있으므로 안전장치와 충돌 화면이 준비된 후 제공합니다.

## 1. 기본 Git 작업

### 1.1 Commit

제공할 화면과 동작:

- 변경 파일과 staged 파일을 구분해 표시
- 파일 여러 개 또는 부분 변경 stage/unstage
- 파일 diff 미리보기
- 커밋 메시지 제목과 본문 입력
- amend 선택 기능
- 커밋 전 작성자 이름과 이메일 확인
- 커밋 성공 후 상태와 history 자동 갱신

주요 Git 명령:

```text
git status --porcelain=v2 -z
git diff --no-color -- <path>
git diff --cached --no-color -- <path>
git add -- <path...>
git restore --staged -- <path...>
git commit -m <message>
git commit --amend
```

완료 조건:

- 공백, 한글과 특수문자가 포함된 파일명을 처리한다.
- 빈 메시지와 staged 파일이 없는 커밋을 명확히 안내한다.
- Git hook이 실패하면 hook의 stderr와 종료 코드를 보여준다.
- Git 명령 실행 중 UI가 멈추지 않는다.

### 1.2 Fetch

- remote를 선택하거나 전체 remote를 fetch할 수 있다.
- 진행 상태와 인증 대기 상태를 표시한다.
- fetch 후 뒤처짐/ahead 상태와 원격 브랜치를 갱신한다.
- prune 옵션은 의미를 설명하고 사용자가 선택하게 한다.

```text
git remote -v
git fetch <remote>
git fetch --all
git fetch --prune <remote>
```

### 1.3 Pull

- 대상 remote와 upstream branch를 명확히 표시한다.
- merge 방식과 rebase 방식을 선택할 수 있다.
- 작업 트리가 깨끗하지 않으면 pull 전에 경고하고 stash/commit/취소를 선택하게 한다.
- 충돌 발생 시 충돌 해결 화면으로 이동한다.

```text
git pull --ff-only
git pull --rebase
git branch --show-current
git rev-parse --abbrev-ref --symbolic-full-name @{upstream}
```

기본값은 예기치 않은 merge commit을 막기 위해 `--ff-only`를 우선 검토합니다. 사용자의 Git 설정을 무시해도 되는지는 설정 화면에서 결정합니다.

### 1.4 Push

- push할 remote와 branch를 보여준다.
- 최초 push에는 upstream 설정 여부를 확인한다.
- 일반 push와 tag push를 구분한다.
- force push는 기본 화면에서 숨기고 `--force-with-lease`만 고급 옵션으로 제공한다.
- `--force`는 제공하지 않거나 매우 강한 확인 과정을 둔다.

```text
git push <remote> <branch>
git push --set-upstream <remote> <branch>
git push --tags <remote>
git push --force-with-lease <remote> <branch>
```

### 1.5 Merge

- 병합할 branch와 현재 branch를 동시에 표시한다.
- fast-forward 가능 여부를 미리 검사한다.
- 병합 전 작업 트리 상태를 검사한다.
- 충돌 파일 목록, ours/theirs/base 비교와 해결 완료 표시를 제공한다.
- merge continue와 abort를 제공한다.

```text
git merge --no-commit <branch>
git merge --continue
git merge --abort
git diff --name-only --diff-filter=U
```

#### 자체 3-way merge 인터페이스

충돌 파일을 외부 도구에만 맡기지 않고 GitCanvas 안에서 해결할 수 있어야 합니다.

```text
┌─────────────────┬──────────────┬────────────────────┐
│ Ours(branch 명) │ Result       │ Theirs(branch 명)  │
│ 현재 branch     │ 현재 branch   │ 병합할 branch      │
└─────────────────┴──────────────┴────────────────────┘
```

- base, ours와 theirs를 나란히 표시하고 최종 결과 패널을 함께 제공한다.
- 변경 줄과 충돌 구간을 정렬하고 색상으로 구분한다.
- 충돌 단위로 ours 사용, theirs 사용, 둘 다 사용과 직접 편집을 제공한다.
- 선택 결과 반영, 실행 취소, 이전/다음 충돌 이동과 키보드 단축키를 제공한다.
- 해결된 충돌과 남은 충돌 개수를 표시하고 저장 전 최종 diff를 보여준다.
- 줄바꿈 형식, 파일 인코딩과 마지막 newline을 가능한 한 보존한다.
- binary, rename/delete, add/add와 submodule 충돌은 전용 안내를 제공한다.
- merge뿐 아니라 rebase, cherry-pick과 revert 충돌에도 같은 편집기를 재사용한다.

```text
git ls-files -u -z
git show :1:<path>   # base
git show :2:<path>   # ours
git show :3:<path>   # theirs
git diff --cc -- <path>
git add -- <resolved-path>
```

큰 파일은 전체 문서를 여러 번 복제하지 않고 줄 인덱스와 변경 구간 중심으로 처리합니다.

### 1.6 Branch

- 로컬 branch와 원격 branch를 구분해 표시한다.
- 생성, 전환, 이름 변경과 삭제를 지원한다.
- upstream 설정과 tracking 상태를 표시한다.
- 병합되지 않은 branch 삭제에는 추가 확인을 요구한다.

```text
git branch --format=<machine-readable-format>
git switch <branch>
git switch -c <new-branch>
git branch -m <new-name>
git branch -d <branch>
git branch --set-upstream-to=<remote>/<branch>
```

### 1.7 로컬 Git 기능 전체 범위

“전체 기능”은 Git의 저수준 내부 명령을 전부 개별 버튼으로 만든다는 뜻이 아닙니다. 일반 사용자가 저장소를 관리하는 명령은 전용 GUI로 제공하고, 드문 고급 기능은 검증된 고급 실행 화면으로 보완합니다.

| 기능군 | 필수 기능 |
|---|---|
| 작업 트리 | status, diff, add, restore, rm, mv, clean, ignore |
| 커밋 | commit, amend, sign-off, revert, cherry-pick |
| 브랜치 | 생성, 전환, 이름 변경, 삭제, tracking, detached HEAD 안내 |
| 원격 | remote 추가·수정·삭제, fetch, pull, push, prune |
| 이력 | log, graph, show, diff, blame, reflog, shortlog |
| 임시 보관 | stash 생성, 목록, 상세, apply, pop, branch, drop, clear |
| 태그 | lightweight/annotated tag 생성, 조회, 삭제, push, 서명 상태 |
| 이력 변경 | reset, interactive rebase, revert, cherry-pick |
| 병합 | merge, 3-way 충돌 해결, continue, abort, merge-base 확인 |
| 작업 공간 | worktree 생성, 목록, 이동, 잠금, 제거, prune |
| 하위 저장소 | submodule add, init, update, sync, deinit, 상태 확인 |
| 분석·복구 | bisect, reflog 기반 복구, fsck 결과 안내 |
| 설정 | system/global/local/worktree 설정의 출처 조회와 편집 |
| 유지관리 | gc, maintenance, repack을 설명과 안전한 기본값으로 제공 |
| 내보내기 | archive, patch 생성·적용, bundle을 고급 기능으로 제공 |

#### 버튼과 키보드 입력의 명령 변환

- 모든 작업은 구조화된 application command로 표현한다.
- 버튼과 키보드 단축키는 동일한 command를 호출하며 Git 프로세스를 직접 실행하지 않는다.
- 실행 전 대상 저장소, branch/commit/file과 예상 영향을 확인할 수 있어야 한다.
- 셸을 통하지 않고 `QProcess::setProgram("git")`과 `setArguments()`로 실행한다.
- stdin, editor/helper와 stderr progress가 필요한 명령을 구분해 처리한다.
- merge/rebase/cherry-pick/bisect 진행 상태를 감지해 가능한 작업만 활성화한다.

### 1.8 기본/자세히 모드와 Git 명령 미리보기

모든 주요 기능은 초보자를 위한 기본 모드와 숙련자를 위한 자세히 모드를 함께 제공합니다.

#### 기본 모드

- 사용 빈도가 높고 안전한 필수 입력만 표시한다.
- 옵션을 몰라도 일반적인 작업을 완료할 수 있는 권장 기본값을 적용한다.
- 적용된 숨은 기본값이 결과를 크게 바꾼다면 짧은 설명으로 알린다.
- 위험 옵션은 기본 모드에서 숨기거나 사용할 수 없게 한다.

#### 자세히 모드

`자세히` 버튼을 누르면 해당 명령이 지원하는 주요 옵션을 다음 컨트롤로 선택할 수 있습니다.

- boolean flag: 체크박스
- 서로 배타적인 방식: 라디오 버튼 또는 드롭다운
- 옵션이 받는 값: 해당 옵션 바로 옆의 숫자·날짜·경로·패턴 입력 필드
- commit, branch, remote, path 같은 위치 인자: 옵션 영역과 분리된 `인자` 입력 영역
- 여러 값을 받는 옵션: 추가/삭제 가능한 목록
- 자주 쓰는 조합: preset

각 옵션에는 다음 정보를 제공합니다.

- Git 원래 옵션 이름(예: `--ignore-space-change`)
- 사람이 이해하기 쉬운 설명
- 기본값과 현재 선택값
- 다른 옵션과의 충돌 또는 의존 관계
- 성능, 출력 범위와 이력에 미치는 영향
- 지원되는 최소 Git 버전

#### 인자 입력 영역

명령이 값을 요구하면 `자세히` 화면에 옵션 선택 영역과 별도로 `인자` 영역을 제공합니다. 사용자가 전체 명령을 직접 입력하지 않고 필요한 값만 입력하거나 선택하게 합니다.

```text
인자
비교 시작 commit: [HEAD~1             ] [History에서 선택]
비교 종료 commit: [HEAD               ] [History에서 선택]
파일/경로:        [src/main.cpp       ] [찾아보기] [추가]
추가 경로:
  - src/main.cpp                         [삭제]
  - src/git/gitclient.cpp                [삭제]
```

인자 종류에 따라 적절한 입력 방식을 사용합니다.

| 인자 종류 | 입력 방식 |
|---|---|
| commit/revision | 자동완성 입력 + History 선택 버튼 |
| branch/tag | 검색 가능한 드롭다운 |
| remote | 등록된 remote 드롭다운 |
| 파일/디렉터리 | 자동완성 입력 + 찾아보기 버튼 |
| 여러 경로 | 추가/삭제 가능한 목록 |
| 숫자 | 최소·최대값이 있는 spin box |
| 날짜 | 날짜 선택기 또는 Git 날짜 표현식 입력 |
| 정규식/검색어 | 텍스트 입력 + 문법 도움말 |
| enum 값 | 드롭다운 또는 라디오 버튼 |

- 필수 인자는 비어 있으면 실행할 수 없으며 누락된 값을 표시한다.
- 선택적 인자는 사용 여부 체크박스를 켰을 때만 입력 컨트롤을 활성화한다.
- 여러 값을 받는 옵션은 한 문자열에 구분자를 입력시키지 않고 목록으로 관리한다.
- revision과 경로 사이의 `--` 구분자는 앱이 자동으로 추가한다.
- branch, tag와 파일명이 비슷해도 모호하지 않도록 인자 역할을 구조적으로 구분한다.
- 사용자가 입력한 commit, branch와 path는 실행 전에 저장소에서 존재 여부를 검사한다.
- 경로는 가능하면 저장소 기준 상대 경로로 표시하고 저장소 밖 경로는 차단하거나 명확히 경고한다.
- 입력값은 명령 미리보기에 즉시 반영한다.

#### 실제 명령 미리보기

작업 화면에는 최종 조립된 Git 명령을 읽기 전용 텍스트 상자로 표시합니다. 옵션이나 대상을 변경하면 즉시 갱신합니다.

```text
git diff --stat --ignore-space-change -- src/main.cpp
```

- 기본 화면에서도 명령 미리보기는 접을 수 있는 영역 또는 하단 상태 영역으로 항상 접근 가능해야 한다.
- `명령 복사`를 제공해 터미널에서 직접 재현할 수 있게 한다.
- 실제 실행 직전에 확정된 명령을 작업 기록에도 표시한다.
- 파일명과 인자는 모호하지 않게 quoting하여 보여주고, 실제 실행은 셸 문자열이 아닌 인자 배열로 수행한다.
- Windows PowerShell과 POSIX shell의 복사용 quoting 형식이 다르면 현재 운영체제 형식을 기본으로 제공한다.
- token, Authorization 헤더, 비밀번호와 credential helper 응답은 명령 미리보기에도 절대 표시하지 않는다.
- 임시 파일에 저장한 PR 본문이나 commit 메시지는 파일 경로와 용도만 표시하고 민감한 본문 전체는 반복 노출하지 않는다.

화면의 텍스트 상자는 기본적으로 편집할 수 없습니다. 사용자가 문자열을 직접 수정해 임의 명령을 실행하는 방식은 옵션 검증, 상호 배타성 검사와 안전 정책을 우회할 수 있기 때문입니다. 직접 인자 입력이 필요한 경우에는 별도의 고급 명령 실행 화면을 사용합니다.

#### 옵션 모델

UI마다 명령 문자열을 직접 조립하지 않고 공통 옵션 메타데이터와 구조화된 명령 모델을 사용합니다.

```text
GitCommandDefinition
├─ command: diff
├─ supportedOptions
│  ├─ --stat: boolean
│  ├─ --name-only: boolean
│  ├─ --diff-filter: enum/set
│  ├─ --ignore-space-change: boolean
│  ├─ --unified: integer
│  └─ --word-diff: enum
├─ conflicts
├─ minimumGitVersion
└─ riskLevel

GitCommandRequest
├─ selectedOptions
├─ revisions
├─ paths
├─ positionalArguments
└─ workingDirectory
```

이 모델 하나에서 옵션 화면, 검증, 명령 미리보기와 `QProcess` 인자 배열을 생성합니다. 따라서 화면에 보인 명령과 실제 실행된 명령이 달라지는 문제를 방지할 수 있습니다.

#### Diff 화면 예시

기본 화면:

```text
[비교 대상: 작업 폴더 ↔ HEAD ▼] [파일: 전체 ▼]

명령: git diff --
[자세히] [실행]
```

자세히 화면:

```text
표시 방식
[x] 변경 통계 표시              --stat
[ ] 파일 이름만 표시             --name-only
[문맥 줄 수: 3                 ]  --unified=3
[단어 단위 차이: 사용 안 함 ▼ ]  --word-diff

공백 처리
[ ] 공백 변경 무시               --ignore-space-change
[ ] 모든 공백 무시               --ignore-all-space
[ ] 빈 줄 변경 무시              --ignore-blank-lines

파일 필터
[변경 종류: A M R D ...        ]  --diff-filter

인자
비교 시작 commit: [HEAD~1      ] [History에서 선택]
비교 종료 commit: [HEAD        ] [History에서 선택]
파일/경로:        [            ] [찾아보기] [추가]

실행 명령
git diff --stat --ignore-space-change --diff-filter=AM HEAD~1 HEAD --
```

`--name-only`처럼 다른 출력 방식과 충돌할 수 있는 옵션은 조합을 검증하고, 자동 해제할 때 그 이유를 알려야 합니다.

#### 적용 대상

이 UX는 diff에만 한정하지 않고 다음 기능에 공통 적용합니다.

- clone의 depth, partial clone, submodule 옵션
- commit의 amend, sign-off와 author 옵션
- log의 날짜, 작성자, 경로, 정렬과 개수 옵션
- fetch/pull/push의 remote, prune, tags와 전략 옵션
- merge/rebase의 전략 및 충돌 관련 옵션
- reset/clean의 모드와 대상 범위
- blame, stash, tag, worktree, submodule과 archive 옵션

#### 완료 조건

- 기본 모드만으로 일반 작업을 수행할 수 있다.
- 자세히 모드에서 선택한 옵션이 명령 미리보기에 즉시 반영된다.
- 잘못되거나 충돌하는 옵션 조합은 실행 전에 차단하고 이유를 설명한다.
- 미리보기의 논리적 프로그램·인자와 실제 `QProcess` 호출 내용이 일치한다.
- 현재 Git 버전에서 지원하지 않는 옵션은 비활성화한다.
- 명령 미리보기, 복사 결과와 진단 로그에 인증정보가 포함되지 않는다.

#### 고급 명령 실행 화면

전용 UI가 아직 없는 기능을 위한 화면이며 임의 셸 실행기가 되어서는 안 됩니다.

- 실행 프로그램은 `git`으로 고정한다.
- shell operator, 외부 프로그램 실행과 명령 치환을 허용하지 않는다.
- 인자를 토큰 단위로 검증하고 실제 실행 인자를 미리 보여준다.
- reset/clean/reflog expire 등 위험 명령에는 전용 안전 정책을 적용한다.
- 자격 증명, 파일 내용과 민감한 remote URL을 로그에서 제거한다.

## 2. 고급 이력 변경

### 2.1 Reset

세 가지 모드를 설명과 함께 제공해야 합니다.

| 모드 | commit 이동 | staging 변경 | 작업 파일 변경 | 위험도 |
|---|---:|---:|---:|---|
| soft | 예 | 아니요 | 아니요 | 낮음 |
| mixed | 예 | 예 | 아니요 | 중간 |
| hard | 예 | 예 | 예 | 매우 높음 |

```text
git reset --soft <commit>
git reset --mixed <commit>
git reset --hard <commit>
```

안전 요구사항:

- 실행 전 대상 commit과 사라질 변경을 미리 보여준다.
- hard reset은 저장되지 않은 변경이 있으면 이중 확인한다.
- 실행 직전 HEAD를 reflog와 별개로 진단 로그에 기록한다.
- 가능하면 복구 방법과 이전 HEAD를 결과 화면에 보여준다.

### 2.2 Rebase

- 일반 rebase와 interactive rebase를 구분한다.
- interactive 화면에서 pick, reword, squash, fixup, drop과 순서 변경을 지원한다.
- 진행 중 상태, 현재 commit, 충돌 파일을 표시한다.
- continue, skip, abort를 제공한다.
- 이미 push된 commit을 수정하면 경고한다.

```text
git rebase <upstream>
git rebase --continue
git rebase --skip
git rebase --abort
git rebase -i <upstream>
```

interactive rebase는 Git editor 프로토콜을 처리할 별도 helper 프로그램 또는 임시 todo 파일 연동 설계가 필요합니다.

### 2.3 공통 안전 정책

- reset, rebase, force-with-lease, 미병합 branch 삭제는 위험 작업으로 분류한다.
- 확인창에는 명령 이름이 아니라 실제 영향과 대상 branch/commit을 표시한다.
- 실행 중 앱을 닫으려 하면 진행 중 작업을 알린다.
- 실패했을 때 무조건 재시도하지 않고 저장소 상태를 다시 검사한다.

## 3. Git History

### 화면

- commit 그래프, branch 선과 merge 관계
- hash, 제목, 작성자, 이메일, 작성·커밋 시간
- branch와 tag 라벨
- 파일 경로와 작성자 및 날짜 필터
- commit 검색
- 선택 commit의 상세 메시지와 변경 파일
- 부모 commit 대비 diff
- 두 commit 비교
- 파일 history와 blame 진입

### 그래프 직접 조작

- commit을 한 번 선택하면 상세 정보와 현재 HEAD와의 관계를 표시한다.
- commit을 두 번 클릭하거나 컨텍스트 메뉴를 열어 해당 commit checkout(detached HEAD), 해당 commit에서 새 branch 생성, tag 생성을 실행할 수 있다.
- branch 라벨에서는 해당 branch로 switch하고, 선택한 commit 또는 branch를 현재 branch에 merge/rebase할 수 있다.
- 두 commit을 선택해 diff를 비교할 수 있다.
- 선택한 commit으로 reset, revert 또는 cherry-pick을 시작할 수 있다.
- 그래프에서 수행하는 작업도 일반 화면과 같은 영향 미리보기와 확인 정책을 적용한다.
- detached HEAD로 이동할 때는 새 commit이 branch에 속하지 않을 수 있음을 알리고 새 branch 생성 선택지를 함께 제공한다.

그래프는 단순 이미지 파일이 아니라 확대·축소, 스크롤, 선택과 컨텍스트 메뉴를 지원하는 상호작용형 시각화로 구현합니다. 내보내기가 필요할 경우 현재 그래프를 PNG/SVG 이미지로 저장하는 기능을 별도로 제공합니다.

주요 Git 명령:

```text
git log -z --date=iso-strict --format=<machine-readable-format>
git show --format=<format> --name-status -z <commit>
git diff <commit-a> <commit-b> -- <path>
git log --follow -- <path>
git blame --line-porcelain <path>
```

성능 요구사항:

- 전체 history를 한 번에 화면 객체로 만들지 않는다.
- 첫 페이지를 우선 표시하고 스크롤에 따라 추가 로딩한다.
- commit 메타데이터와 그래프 레이아웃을 캐시한다.
- 필터 변경과 저장소 전환 시 이전 작업을 취소할 수 있어야 한다.
- 매우 큰 diff는 크기 경고 후 점진적으로 표시한다.

## 4. 사용자 계정

Git에는 서로 다른 두 종류의 계정 정보가 있습니다.

### 4.1 Git 작성자 정보

commit에 기록되는 `user.name`과 `user.email`입니다. GitHub 로그인 계정과 자동으로 같다고 가정하면 안 됩니다.

- 전역 설정과 저장소별 설정을 구분해 표시한다.
- 현재 commit에 실제 적용될 값을 미리 보여준다.
- 이름과 이메일을 변경할 수 있다.
- GitHub의 noreply 이메일 사용 여부를 선택할 수 있다.

```text
git config --global user.name
git config --global user.email
git config --local user.name
git config --local user.email
git config --show-origin --get-regexp ^user\.
```

### 4.2 GitHub 로그인과 토큰

#### 초기 구현: GitHub CLI 연동

개발 속도와 보안을 위해 설치된 `gh`가 있으면 다음 기능을 사용합니다.

```text
gh auth login --web
gh auth status
gh auth switch --user <account>
gh auth logout --user <account>
gh auth setup-git
```

GitHub CLI는 가능한 경우 토큰을 운영체제 자격 증명 저장소에 보관합니다. GitCanvas는 토큰 문자열을 로그, 명령행, 설정 파일 또는 화면에 출력하지 않습니다.

#### 독립 구현: GitHub App Device Flow

향후 `gh` 없이 로그인하려면 GitHub App을 등록하고 Device Flow를 사용합니다.

1. GitCanvas가 GitHub에서 기기 코드와 사용자 코드를 요청한다.
2. 사용자에게 일회용 코드와 GitHub 인증 URL을 보여준다.
3. 사용자가 브라우저에서 승인한다.
4. GitCanvas가 지정된 간격으로 승인 상태를 확인한다.
5. 받은 토큰은 OS 보안 저장소에 저장한다.

Linux에서는 Secret Service/libsecret, Windows에서는 Credential Manager를 사용합니다. Qt `QSettings`나 평문 파일에 토큰을 저장하지 않습니다.

#### 계정 전환

- 로그인된 GitHub 계정 목록과 현재 활성 계정을 표시한다.
- 계정별 사용자명, avatar와 접근 가능한 저장소 정보를 표시한다.
- 계정 전환 시 해당 저장소의 remote URL 및 credential 적용 범위를 안내한다.
- 로그아웃 시 로컬 Git 작성자 설정을 지울 것인지 별도로 묻는다.

GitHub 인증 계정 전환과 `user.name/email` 변경은 별도 동작입니다.

#### 계정별 권한과 Repository scope

여러 계정을 등록하더라도 모든 저장소를 한 목록에 무조건 합치지 않습니다. 활성 계정과 GitHub App 설치 권한을 기준으로 현재 접근 가능한 범위를 계산합니다.

- 계정마다 GitHub 사용자 ID, login, avatar, host와 인증 상태를 구분한다.
- 개인 저장소, 조직 저장소와 GitHub App installation별 저장소 범위를 구분한다.
- public/private/internal 가시성과 read/write/admin 권한을 표시한다.
- 활성 계정을 바꾸면 저장소 목록을 다시 조회하고 계정별 cache를 섞지 않는다.
- 현재 계정으로 접근할 수 없는 로컬 저장소는 삭제하지 않고 원격 접근 불가로 표시한다.
- 조직 SSO 승인 필요, App 미설치, token 만료와 권한 제거를 서로 다르게 표시한다.
- 계정 전환 시 진행 중인 API 요청을 취소하고 새 계정 컨텍스트에서 다시 시작한다.
- push, PR과 merge 기능은 현재 권한 및 branch protection 상태에 따라 활성화한다.

쓰기 작업 직전 서버 권한과 대상 상태를 다시 검증하며 기능에 필요한 최소 권한만 요청합니다.

## 5. 저장소 등록, 조회와 Clone

### 5.1 로컬 저장소 등록

- 폴더 선택으로 기존 저장소를 등록한다.
- 폴더를 드래그 앤 드롭해 등록한다.
- 최근 저장소 목록, 즐겨찾기와 제거 기능을 제공한다.
- 등록은 디스크의 저장소를 삭제하지 않고 앱 목록에만 추가한다.
- 중복 경로와 존재하지 않는 경로를 처리한다.
- 상위 작업 트리와 worktree를 올바르게 식별한다.

```text
git rev-parse --show-toplevel
git rev-parse --git-common-dir
git worktree list --porcelain
```

### 5.2 GitHub 저장소 조회

- 활성 GitHub 계정이 접근 가능한 개인, 조직 및 private 저장소를 조회한다.
- 이름, owner, 최근 갱신일, clone 여부로 필터링한다.
- pagination과 API rate limit을 처리한다.
- GitHub App을 사용할 경우 해당 앱이 설치되고 권한이 부여된 저장소만 보일 수 있음을 표시한다.

초기에는 `gh repo list` 또는 GitHub API를 사용하고, 이후 GitHub App installations API로 확장합니다.

### 5.3 Clone

- HTTPS와 SSH clone URL 중 선택한다.
- 대상 상위 폴더와 생성될 폴더명을 미리 보여준다.
- 같은 이름의 경로가 존재하면 덮어쓰지 않는다.
- clone 진행률과 취소 기능을 제공한다.
- 완료 후 자동으로 로컬 저장소 목록에 등록한다.
- **전체 이력 포함** 옵션을 제공하고 기본값을 켠다. 이 경우 별도의 depth 제한 없이 전체 commit과 Git log를 내려받는다.
- 전체 이력 포함을 끄면 shallow clone임을 설명하고 받을 최근 commit 수(depth)를 입력하게 한다.
- partial clone과 submodule은 별도의 고급 옵션으로 제공하며 shallow clone과 의미가 다름을 설명한다.
- clone 완료 후 실제 shallow 저장소 여부와 조회 가능한 history 범위를 결과 화면에 표시한다.

```text
git clone --progress <url> <directory>
git clone --depth <n> <url> <directory>
git clone --filter=blob:none <url> <directory>
git clone --recurse-submodules <url> <directory>
```

Git 진행률은 주로 stderr에 출력되므로 stdout과 stderr를 별도로 수집해야 합니다.

옵션 설명 예시:

- **전체 이력 포함(기본):** 모든 commit과 branch 이력을 받아 전체 Git log를 조회하고 과거 commit으로 이동할 수 있습니다. 저장소가 크면 시간과 디스크 사용량이 늘어납니다.
- **최근 이력만 받기:** 지정한 개수의 최근 commit만 받아 clone을 빠르게 끝냅니다. 오래된 log 조회와 일부 merge/rebase 작업은 추가 이력을 받은 뒤 사용할 수 있습니다.
- **파일 내용 지연 받기:** commit 이력은 유지하면서 필요한 blob을 나중에 받아 최초 다운로드 용량을 줄입니다.

## 6. SSH 원격 컴퓨터의 Git 사용

### 기능 정의

이 기능은 저장소의 `origin`이 SSH URL이라는 의미가 아닙니다. GitCanvas가 SSH로 다른 컴퓨터에 접속하여 그 컴퓨터에 설치된 Git과 그 컴퓨터의 작업 디렉터리를 조작하는 원격 작업공간 기능입니다.

```text
GitCanvas가 실행되는 PC
    ↓ SSH 접속
원격 컴퓨터의 OS 계정
    ↓ 원격 컴퓨터의 git 실행
원격 컴퓨터의 repository
    ↓ 필요하면 별도 인증
GitHub/GitLab 등의 remote
```

### Scope 모델

화면 상단과 위험 작업 확인창에는 현재 작업 문맥을 항상 표시합니다.

```text
Execution scope
├─ Computer: Local 또는 SSH profile
├─ OS identity: 로컬 사용자 또는 user@host:port
├─ Repository: 해당 컴퓨터 기준 절대 경로
├─ Git identity: 적용되는 user.name / user.email
├─ Forge identity: GitHub host / login / 권한 범위
└─ Remote credential context: 원격 저장소 접근에 사용되는 인증 방식
```

예시:

```text
컴퓨터: build-server (dev@192.0.2.10:22)
저장소: /srv/projects/gitcanvas
Git 작성자: Developer <dev@example.com> (repository local config)
GitHub 계정: work-account @ github.com
GitHub 접근: organization-a/gitcanvas — write
```

`Git 작성자`, `SSH OS 계정`과 `GitHub 로그인 계정`은 서로 다를 수 있으므로 자동으로 같은 계정이라고 가정하지 않습니다.

### SSH 컴퓨터 등록

- 별칭, hostname/IP, port와 SSH username을 등록한다.
- `~/.ssh/config`의 Host 항목을 불러오거나 별도 profile을 만들 수 있다.
- 인증 방식은 ssh-agent, 개인키 경로와 OS가 제공하는 SSH 방식을 지원한다.
- private key 내용과 passphrase를 GitCanvas 설정 파일에 저장하지 않는다.
- 최초 연결 시 host key fingerprint를 보여주고 사용자가 확인하게 한다.
- known_hosts 변경 또는 불일치가 발생하면 자동 수락하지 않고 연결을 차단한다.
- 연결 테스트에서 OS, Git 버전, 홈 디렉터리와 사용 가능한 기능을 읽기 전용으로 확인한다.
- 연결 timeout, keepalive와 명시적 연결 종료를 지원한다.

비밀번호를 명령 인자에 전달하지 않습니다. 대화형 비밀번호 인증을 지원한다면 OS의 askpass/credential UI를 사용하고 로그와 프로세스 인자에서 제거합니다.

### 원격 저장소 등록과 탐색

- SSH profile을 선택한 뒤 원격 경로를 직접 입력하거나 허용된 시작 디렉터리 아래에서 탐색한다.
- `git -C <path> rev-parse --show-toplevel`로 저장소 루트를 확인한다.
- local과 SSH 저장소 목록을 그룹으로 구분한다.
- 같은 문자열 경로라도 컴퓨터가 다르면 서로 다른 저장소 ID로 취급한다.
- 원격 저장소의 최근 사용, 즐겨찾기와 표시 이름은 SSH profile별로 저장한다.
- 연결이 끊긴 원격 저장소는 삭제하지 않고 offline 상태로 표시한다.
- 원격 symlink와 실제 경로를 확인해 허용한 root 밖으로 벗어나지 않게 한다.

저장소 식별자는 단순 경로가 아니라 다음 복합키를 사용합니다.

```text
RepositoryId = ExecutionTargetId + RemoteCanonicalPath + GitCommonDir
```

### 원격 Git 명령 실행

로컬 실행과 원격 실행은 같은 `GitCommandRequest`를 사용하고 executor만 교체합니다.

```text
GitCommandRequest
    ├─ LocalGitExecutor → QProcess(git, arguments)
    └─ SshGitExecutor   → SSH → remote git(arguments)
```

명령 미리보기에는 실행 위치도 함께 표시합니다.

```text
실행 위치: build-server (dev@192.0.2.10)
원격 경로: /srv/projects/gitcanvas
Git 명령: git -C /srv/projects/gitcanvas status --porcelain=v2 -z
전송 형태: ssh build-server -- <원격 Git 요청>
```

SSH의 원격 command는 서버 셸이 해석할 수 있으므로 사용자 입력을 문자열 결합해 전송해서는 안 됩니다. 권장 구현은 작은 `gitcanvas-remote-helper`를 원격에 설치하고 stdin의 길이 제한 JSON/protocol 요청을 받아 검증된 Git argv로 실행하는 방식입니다.

```text
GitCanvas
  → ssh host gitcanvas-remote-helper
  → stdin: versioned request {repository, command, arguments}
  ← stdout: framed result/progress
```

초기 helper 없는 모드를 제공한다면 POSIX 원격만 제한적으로 지원하고, 허용된 Git subcommand 및 엄격한 인자 quoting과 path root 검증을 적용합니다. 원격 shell 종류를 확인할 수 없으면 쓰기 명령을 실행하지 않습니다.

### 파일과 Diff 처리

- status/log 같은 구조화된 출력은 SSH stdout을 스트리밍 파싱한다.
- stderr progress와 오류를 stdout과 분리한다.
- diff와 파일 내용은 크기 제한 및 점진적 로딩을 사용한다.
- 원격 파일을 merge editor에서 수정할 때 버전 식별자와 hash를 기록해 동시 변경을 감지한다.
- 저장 전 원격 파일이 바뀌었으면 덮어쓰지 않고 재비교를 요구한다.
- 임시 파일은 로컬/원격 위치와 삭제 시점을 기록하고 작업 종료 시 정리한다.
- 네트워크 중단 시 부분적으로 전송된 파일을 최종 결과로 저장하지 않는다.

### 두 단계 인증과 계정 scope

다음 두 연결은 독립적입니다.

```text
1. 로컬 PC → SSH 원격 컴퓨터
   인증 주체: SSH user/key/agent

2. 원격 컴퓨터 → GitHub remote
   인증 주체: 원격 SSH key, 원격 credential helper 또는 전달된 agent
```

- 로컬 GitHub access token을 원격 컴퓨터에 자동 전송하지 않는다.
- 로컬과 원격의 `gh auth` 상태 및 credential helper를 별도로 표시한다.
- 원격 GitHub 계정과 repository scope는 원격 문맥에서 다시 확인한다.
- 로컬에서 GitHub API만 조회할 때 사용하는 계정과 원격 `git push` 인증 계정이 다르면 경고한다.
- 계정/컴퓨터 조합마다 저장소 접근 cache와 rate-limit 상태를 분리한다.
- push 전에 예상 GitHub 계정과 대상 owner/repository를 확인할 수 있게 한다.

원격 컴퓨터에서 GitHub에 접근하는 인증 방식:

| 방식 | 기본 정책 | 설명 |
|---|---|---|
| 원격 컴퓨터의 전용 SSH key | 권장 | 원격 host에서 관리하며 필요한 저장소 권한만 부여 |
| 원격 credential helper | 허용 | 원격 OS 보안 저장소와 정책을 사용 |
| SSH agent forwarding | 기본 꺼짐 | 신뢰하는 host에서 사용자가 명시적으로 활성화 |
| 토큰 환경변수 전달 | 금지 | 프로세스·로그·원격 환경 노출 위험 |
| private key 파일 복사 | 금지 | GitCanvas가 로컬 private key를 원격에 복사하지 않음 |

agent forwarding을 켜면 원격 host가 연결 중 로컬 agent에 서명 요청을 보낼 수 있으므로 신뢰할 수 있는 host에만 사용하고 scope 화면에 활성 상태를 강조합니다.

### 원격 작업 UX

- 창 헤더, 탭, 저장소 목록과 위험 작업 창에 `LOCAL` 또는 `SSH: alias` 배지를 표시한다.
- 로컬과 원격 저장소를 색상만으로 구분하지 않고 텍스트 및 아이콘을 함께 사용한다.
- 명령 실행 전에 대상 컴퓨터와 경로를 바꿀 수 없게 고정하거나 재확인한다.
- reset --hard, clean, branch 삭제와 강제 push는 원격 작업일 때 대상 host 이름을 직접 확인하게 한다.
- 연결 상태, 왕복 지연, 실행 중, 재연결과 offline 상태를 표시한다.
- 연결이 끊어졌다고 쓰기 명령을 자동 재실행하지 않는다. 결과 상태를 조회한 뒤 재시도한다.
- 키보드 단축키도 현재 활성 scope에서만 작동하며 background tab 저장소에 적용되지 않는다.

### 완료 조건

- local과 여러 SSH profile의 저장소를 동시에 등록할 수 있다.
- 모든 화면에서 현재 computer/repository/account scope를 확인할 수 있다.
- 원격 Git 버전 및 기능 차이를 감지해 옵션을 활성화한다.
- 공백, 한글과 특수문자가 있는 원격 경로 및 파일을 처리한다.
- 원격 명령에 사용자 입력을 안전하지 않은 셸 문자열로 결합하지 않는다.
- host key 검증을 우회하지 않으며 key/token/passphrase를 로그에 남기지 않는다.
- 네트워크 중단과 timeout 후 저장소 상태를 다시 확인한다.
- 로컬 토큰과 private key를 원격에 자동 복사하거나 전달하지 않는다.
- 읽기/쓰기/위험 명령을 각각 통합 테스트한다.

## 8. GitHub Pull Request

### Git과 Pull Request의 차이

Pull Request는 Git 자체 기능이 아니라 GitHub가 제공하는 협업 기능입니다. `git push`로 branch를 서버에 올릴 수는 있지만, `git` CLI만으로 GitHub Pull Request를 생성하거나 리뷰할 수는 없습니다.

GitCanvas에서는 역할을 다음처럼 분리합니다.

```text
commit, branch, fetch, push, merge → git CLI
Pull Request, 리뷰, 댓글, CI 상태 → GitHub CLI(gh) 또는 GitHub API
```

GitLab의 Merge Request나 다른 호스팅 서비스까지 지원하려면 서비스별 provider 계층을 별도로 구현해야 합니다.

### 초기 구현: GitHub CLI 사용

초기 버전은 GitHub CLI의 인증과 JSON 출력을 사용해 개발 속도를 높입니다.

```text
gh pr create
gh pr list --json <fields>
gh pr view <number> --json <fields>
gh pr checkout <number>
gh pr diff <number>
gh pr checks <number>
gh pr review <number>
gh pr comment <number>
gh pr merge <number>
gh pr close <number>
gh pr reopen <number>
gh pr update-branch <number>
```

화면에서 필요한 값은 대화형 프롬프트에 맡기지 않고 명령 인자로 전달하며, 조회 결과는 사람이 읽는 출력 대신 `--json`으로 받습니다.

### PR 생성 화면

- 현재 head branch와 대상 base branch를 표시한다.
- 아직 push되지 않은 commit이 있으면 먼저 push할지 확인한다.
- 제목, 본문, draft 여부, reviewer, assignee와 label을 입력한다.
- 저장소의 Pull Request template을 불러온다.
- base와 head 사이의 commit 및 파일 diff를 미리 보여준다.
- fork 기반 PR을 지원한다.
- 성공하면 PR 번호와 URL을 표시한다.
- reviewer 및 team review 요청, assignee, milestone, project와 label 지정은 계정 권한에 따라 제공한다.

예상 명령:

```text
gh pr create --base <base> --head <head> --title <title> --body-file <file>
gh pr create --draft ...
```

본문은 길거나 특수문자를 포함할 수 있으므로 가능하면 임시 파일 또는 표준입력으로 전달하고, 진단 로그에 본문 전체를 기록하지 않습니다.

### PR 목록과 상세 화면

- open, closed, merged와 draft 상태를 필터링한다.
- 작성자, reviewer, branch와 label로 검색한다.
- 제목, 본문, commit, 변경 파일, 댓글과 리뷰를 표시한다.
- merge 가능 여부와 충돌 상태를 표시한다.
- GitHub Actions 등 CI check 상태를 표시하고 갱신한다.
- 선택한 PR branch를 로컬에 checkout할 수 있다.

### 리뷰와 요청 보내기

다음 GitHub 요청을 UI에서 보낼 수 있습니다.

- 일반 댓글 작성
- approve 리뷰
- 변경 요청(request changes)
- reviewer에게 리뷰 요청
- draft를 ready for review로 변경
- PR 닫기 및 다시 열기
- base branch 최신 상태로 PR branch 갱신
- 특정 사용자 또는 team에 리뷰 요청 및 재요청
- 리뷰 요청 취소
- 코드 줄 단위 review comment와 discussion 해결 상태 표시

```text
gh pr comment <number> --body-file <file>
gh pr review <number> --approve
gh pr review <number> --request-changes --body-file <file>
gh pr ready <number>
```

### PR 병합

- merge commit, squash와 rebase merge를 구분한다.
- branch protection, 필수 리뷰와 CI check 상태를 보여준다.
- head commit이 화면을 연 이후 변경되지 않았는지 확인한다.
- 병합 후 remote branch 삭제 여부를 선택한다.
- 관리자 권한 우회 옵션은 초기 버전에서 제공하지 않는다.

```text
gh pr merge <number> --merge
gh pr merge <number> --squash
gh pr merge <number> --rebase
gh pr merge <number> --match-head-commit <sha>
```

### 향후 구현: GitHub API 직접 요청

`gh` 의존성을 제거하거나 더 정교한 UI가 필요하면 Qt Network를 사용해 GitHub REST 또는 GraphQL API에 HTTPS 요청을 보낼 수 있습니다.

```text
GitCanvas UI
    ↓
GitHubProvider
    ├─ GhCliBackend
    └─ GitHubApiBackend
```

API 요청에는 GitHub 로그인으로 얻은 토큰을 `Authorization` 헤더에 넣습니다. 토큰을 URL, 명령행, 로그 또는 오류 메시지에 넣지 않습니다. timeout, 취소, pagination, rate limit, 권한 부족과 토큰 만료를 각각 처리해야 합니다.

Pull Request와 관계없는 일반 GitHub REST 요청도 같은 `GitHubApiBackend`를 통해 보낼 수 있지만, 허용된 API endpoint와 필요한 최소 권한을 기능별로 명시해야 합니다. 사용자가 임의의 URL과 토큰을 조합하는 범용 HTTP 클라이언트 기능은 제공하지 않습니다.

### 완료 조건

- 로그인하지 않은 상태에서 필요한 인증 절차를 안내한다.
- GitHub 저장소가 아닌 remote에서는 PR 버튼을 비활성화하고 이유를 표시한다.
- PR 생성 전 branch가 원격에 존재하는지 검사한다.
- 네트워크 요청 중 UI가 멈추지 않으며 취소할 수 있다.
- API 및 CLI 결과에서 token과 민감정보를 로그에 남기지 않는다.
- 권한 부족, rate limit, SSO 승인 필요와 네트워크 오류를 구분한다.
- PR 생성 같은 요청은 재시도로 중복 생성되지 않도록 결과를 먼저 확인한다.

## 9. 오류 처리와 원인 추적

### 오류 표시 원칙

오류창은 최소한 다음 정보를 포함합니다.

- 무엇을 하려다 실패했는가
- 사용자 데이터가 변경되었는가
- 가장 가능성 높은 원인
- 사용자가 지금 할 수 있는 조치
- 상세 정보와 진단 ID

예시:

```text
Push에 실패했습니다.

원인: 원격 branch에 로컬에 없는 commit이 있습니다.
상태: 원격 저장소는 변경되지 않았습니다.
조치: Fetch 후 변경 내용을 확인하고 Pull 또는 Rebase를 실행하세요.

[Fetch 실행] [상세 정보 복사] [닫기]
```

### 수집할 진단 정보

- 작업 종류와 시작/종료 시간
- 실행한 Git 프로그램 경로와 Git 버전
- 현재 저장소 경로를 익명화한 식별자
- Git 인자 목록에서 token과 개인정보를 제거한 값
- 종료 코드와 process error
- stdout/stderr의 제한된 크기 복사본
- 현재 branch, HEAD와 작업 트리 상태
- 운영체제, 앱 버전과 Qt 버전
- 연관된 작업을 묶는 고유 진단 ID

### 절대 기록하지 않을 정보

- GitHub access/refresh token
- Authorization 헤더
- 비밀번호와 credential helper 응답
- SSH private key
- 사용자가 입력한 전체 commit 내용이나 파일 내용
- remote URL에 포함된 자격 증명

### 오류 분류

- 환경 오류: Git/gh 없음, PATH, 권한, 디스크 공간
- 입력 오류: 빈 commit 메시지, 잘못된 branch 이름
- 저장소 상태 오류: 충돌, detached HEAD, 진행 중 rebase/merge
- 인증 오류: 토큰 만료, 권한 부족, SSO 승인 필요
- 네트워크 오류: DNS, TLS, timeout, proxy
- 원격 상태 오류: non-fast-forward, protected branch
- 앱 오류: 파싱 실패, 예상하지 못한 Git 출력, crash

### 원인 추적 과정

1. 실행 전에 저장소 상태를 기록한다.
2. Git 명령과 각 프로세스 결과를 동일한 진단 ID로 연결한다.
3. 종료 코드와 stderr 패턴으로 1차 분류한다.
4. 필요한 경우 읽기 전용 진단 명령으로 현재 상태를 다시 확인한다.
5. 사용자에게 원문 stderr와 이해하기 쉬운 설명을 함께 제공한다.
6. 복구 가능한 경우 abort, retry, fetch 등의 버튼을 제공한다.
7. 사용자가 선택했을 때만 삭제 처리된 진단 보고서를 파일로 내보낸다.

문자열 패턴만으로 오류를 단정하지 않습니다. Git 버전과 locale에 따라 메시지가 달라질 수 있으므로 종료 코드, 저장소 상태와 machine-readable 출력을 함께 사용합니다.

### 로그 보관 정책

- 기본 로그 수준은 작업 이름, 결과와 진단 ID만 기록한다.
- 상세 진단 로그는 사용자가 설정에서 활성화한다.
- 로그 파일 크기와 보관 개수를 제한한다.
- 오류 보고서 생성 전 민감정보 필터를 다시 적용한다.
- UI에서 로그 위치 열기, 복사 및 삭제 기능을 제공한다.

## 공통 완료 기준

모든 필수 기능은 다음 조건을 충족해야 완료로 봅니다.

- Windows와 지원 Ubuntu 버전에서 동작한다.
- Git 작업 중 UI가 멈추지 않는다.
- 취소 가능한 작업은 안전하게 취소된다.
- 공백, 한글과 특수문자가 있는 경로를 처리한다.
- 명령 문자열을 셸로 조립하지 않고 프로그램과 인자를 분리한다.
- 성공, 실패와 부분 성공 상태를 구분한다.
- 위험 작업에는 영향 미리보기와 확인 과정이 있다.
- 인증정보가 로그나 설정 파일에 평문으로 남지 않는다.
- 단위 테스트 또는 통합 테스트와 사용자 문서가 있다.

## 아직 결정해야 할 사항

- GitHub OAuth App과 GitHub App 중 독립 인증의 최종 방식
- GitHub Enterprise Server 지원 범위
- 부분 stage를 자체 diff 편집기로 구현할지 Git helper를 사용할지
- merge/rebase 충돌 편집기를 내장할지 외부 편집기와 병행할지
- Git LFS와 submodule을 최초 정식 버전에 포함할지
- Windows/Linux 보안 저장소 추상화에 사용할 라이브러리
