# 전체 Git 기능의 GUI 확장

작업 순서 13의 목표는 **모든 명령과 옵션을 GUI로 조작**하는 것입니다. 이번 변경은 명령별 옵션 폼과 누락된 기능별 화면을 추가합니다. 명령을 폼으로 구성할 수 있는 범위와 개별 동작·복구까지 검증한 범위는 구분합니다. 모든 Git 기능의 전용 처리 흐름을 완료한 상태는 아닙니다.

## 명령별 옵션 폼

**Git Tools → 전체 Git 명령 · 옵션 GUI**를 엽니다. 창은 제목 표시줄 없이 열립니다.

1. 명령 이름을 검색하고 선택합니다. 앱이 실제로 사용하는 Git의 `--list-cmds=main` 결과를 사용합니다.
2. 왼쪽에서 옵션 이름 또는 설명을 검색합니다. 옵션을 선택하면 해당 설명을 읽을 수 있습니다. **전체 설명서 보기**로 문맥·예제·제한도 확인합니다.
3. 옵션을 더블 클릭하거나 **선택 옵션 추가**를 누릅니다. 오른쪽에서 필요한 값을 입력합니다. 값이 선택 사항이면 **값 전달** 체크로 생략하거나 전달합니다. 빈 문자열 전달과 값 생략은 다릅니다.
4. 같은 옵션을 반복해서 추가하거나 ↑/↓로 순서를 조정합니다. 설명서의 COMMANDS/SUBCOMMANDS/MODES에 나온 하위 명령은 드롭다운에서 추가합니다. 명령에 따라 하위 명령보다 먼저 필요한 전역 옵션도 순서를 바꾸어 배치합니다.
5. 커밋·경로·패턴은 **대상 값 추가**로 각각 넣습니다. 옵션으로 해석되면 안 되는 경로는 **경로 구분자 추가**로 넣은 `--` 뒤에 배치합니다. `--`를 지원하지 않는 명령도 있으므로 설명서를 확인합니다.
6. **조회 / 실행 미리보기**에서 저장소와 정확한 인자 배열을 확인하고 **확인 후 실행**을 누릅니다. 입력을 바꾸면 이전 미리보기가 무효화됩니다.

셸 명령줄을 작성하지 않습니다. 인자 안의 공백·따옴표·개행·`$()`·`;`는 그대로 하나의 인자로 전달합니다. 메시지 옵션에는 여러 줄을 입력할 수 있습니다. 파이프·리다이렉션을 해석하지 않습니다.

### 설명서와 지원 범위

- 설치된 Git의 `--html-path` 아래 `git-<명령>.html`을 읽습니다. Git for Windows에 포함된 설명서로 검증했습니다. 설명서 패키지가 없으면 폼을 만들지 않고 그 이유를 표시합니다. 네트워크에서 문서를 자동 다운로드하거나 다른 Git 버전의 옵션을 섞지 않습니다.
- 플래그, 필수 값, 선택 값, `--name=value`, 짧은 옵션, `--[no-]` 변형, `-<숫자>` 및 `-L:<함수>:<파일>` 표기를 처리합니다.
- 옵션 설명은 Git 설명서의 영어 원문입니다. 앱의 조작 버튼과 새 기능별 화면은 한/영 번역을 제공합니다.
- 설명서의 정의 목록에 없는 옵션, 문맥에 따라 의미가 달라지는 동일 이름의 옵션, 실행 환경에 따라 생기는 옵션까지 자동으로 알아내지는 못합니다. 해석하지 못한 복합 표기는 개수와 원문을 표시합니다. 명령 간·옵션 간 제약은 아직 Git의 검증을 이용합니다.
- 내부 helper, 서버 프로토콜 프로세스, 임의 별칭·확장, 대화형 패치/편집기 등은 일반 폼 실행으로 대체하지 않습니다. Push/Pull은 기존 Fetch 선행 동기화 화면, 충돌·진행 작업은 기존 Continue/Abort·3-way 화면을 이용합니다. 이러한 작업의 모든 옵션을 전용 GUI로 연결하는 일은 남아 있습니다.
- 이 창의 명령은 모두 보수적으로 쓰기로 분류합니다. 예를 들어 `log --output`은 파일을 쓰므로 명령 이름만 보고 읽기로 분류하지 않습니다. 실행 중 강제 중단이나 자동 재실행을 하지 않습니다.
- Git hook·서명 도구·Git 기능이 실행하는 외부 프로그램을 격리하는 샌드박스는 아닙니다. 전역 Git 옵션과 사용자 환경 설정 전체를 편집하는 화면도 아닙니다.

## 바이너리 표준 입력·출력

텍스트 stdin 대신 **바이너리 입력**에 기존 파일을 지정할 수 있습니다. 텍스트와 파일 입력은 동시에 사용하지 않습니다. 입력 파일은 미리보기 당시의 SHA256을 실행 직전에 재검사합니다.

**바이너리 출력**에 새 파일을 지정하면 Git stdout 원본 바이트를 저장합니다. 화면에 덧붙이는 복구 참조나 진단 메시지는 출력 파일에 넣지 않습니다. stderr도 섞지 않습니다. `hash-object`·`cat-file`·`archive` 등에서 사용할 수 있습니다.

입력·출력은 각각 **8 MiB 이하**입니다. 출력은 성공한 명령의 결과만 저장하며 기존 파일을 덮어쓰지 않습니다. 저장 공간 부족이나 실행 도중 다른 프로그램이 출력 파일을 만든 경우, Git 작업은 이미 반영되었을 수 있으므로 명령을 다시 실행하기 전에 상태를 확인합니다. 저장 실패 시 일부 출력 파일이 남을 수 있습니다. 대형 팩 파일의 무제한 스트리밍·상호 대화형 프로토콜은 후속 범위입니다.

## 추가한 기능별 화면

| 분야 | 추가 기능 |
|---|---|
| Notes | 참조 선택, 목록·보기·추가·이어 쓰기·복사·제거 |
| Replace | 객체 대체 목록·연결·해제 |
| 설정 | 같은 키의 다중 값 조회·추가·정확히 일치하는 값만 제거 |
| Sparse checkout | Cone 폴더 선택·추가·목록·재적용·전체 파일 복원 |
| Worktree | 분리 HEAD 폴더 생성·외부에서 이동한 연결 복구 |
| Submodule | 추가·deinit·URL·추적 브랜치·커밋 차이 |
| LFS | 환경·파일·잠금 목록, lock/unlock, fetch/push, 정리 미리보기·이력 변환 분석 |
| 서명 | 키 지정 서명 태그 생성·태그/커밋 서명 검증 |
| Rerere | 기록 중인 충돌·차이·남은 경로 조회 |
| 점검 | Commit graph 생성·검증, 참조 압축 |

Notes를 수정할 때 기존 Notes 참조를 보관합니다. 객체 대체 해제는 대체 참조를 보관하고 예상 객체 ID로 삭제합니다. 복구 참조는 `refs/gitcanvas/tool-backups/` 아래에 남습니다. HEAD 참조만으로 설정·미커밋 파일·서버의 전체 상태를 복구할 수는 없습니다.

Sparse 폴더 선택은 깨끗한 작업 상태에서 실행하며, 규칙 파일이 미리보기 뒤 변경되면 다시 확인해야 합니다. Submodule deinit은 하위 저장소의 변경·미추적·무시 파일도 검사하고 강제 삭제하지 않습니다. LFS Push는 **LFS 객체 업로드**이며 Git 브랜치 Push와 별개입니다.

## 검증과 다음 작업

실제 임시 Git 저장소에서 Notes·Replace·다중 설정·Sparse·분리 Worktree·Submodule 보호·Commit graph·바이너리 입출력과 기존 Git Tools의 회귀를 검사합니다. 옵션 폼에서는 실제 Git 설명서 읽기, 검색·선택·메시지 개행 보존·미리보기 무효화·실제 실행을 검사합니다. 테스트는 `build/git-command-coverage.json`에 설치된 설명서별 옵션 수와 미해석 항목을 기록합니다. 이 숫자는 실행 성공이나 전용 안전 검증의 개수가 아닙니다.

Windows의 Git **2.55.0.windows.5** 설명서에서 **158개 명령·3,493개 옵션 항목**의 폼 구성을 확인했습니다. 기능별 입력 화면은 **42개 작업**을 추가했습니다. 명령마다 중복되는 옵션도 각각 집계하며, 설명서가 없는 내부 helper는 이 숫자에 포함되지 않습니다.

전체 전용 GUI 목표에서 남은 주요 작업:

1. 명령별·하위 명령별 옵션 스키마와 상호 배타/필수 조건, 경로·참조·키 등의 선택 위젯, 문맥별 설명 번역.
2. Push/Pull 고급 refspec·shallow/partial, 대화형 Bisect 검사·재개, 모든 rebase 모드 등 전용 실행 흐름.
3. LFS migrate 실행·복구, 서버 잠금 경합, 서명 키·에이전트·인증 실패의 실제 환경 검증.
4. 대용량 바이너리 스트리밍, 확장 프로그램·별칭의 명시적 실행 정책과 UI, 서버 프로세스 수명 관리.
5. 모든 지원 명령·옵션 조합에 대한 버전별 실행·실패·복구 커버리지.

새 옵션을 폼에서 선택할 수 있다는 이유로 위 항목을 완료 처리하지 않습니다.
