# 공통 작업 상태·중단·복구

작업 순서 4번의 구현 안내입니다. 메인 화면의 **작업 상태 · 복구** 탭에서 확인합니다. 진행 작업·충돌·잠금이 있으면 탭 이름에 `(!)`를 표시합니다.

## 현재 상태 확인

- 저장소를 열거나 새로고침할 때 Git 관리 디렉터리, 진행 중인 작업, 충돌 파일, 주요 잠금 파일을 조회합니다.
- Merge, Rebase, Cherry-pick, Revert, git am, sequencer, bisect 상태를 구분합니다. 여러 표시가 함께 있으면 Rebase/AM을 우선합니다.
- 충돌 파일은 Git Index의 unmerged 상태로 판단합니다. 파일을 수정한 것만으로 해결되지 않으며, 변경 사항 탭에서 **Stage**해야 충돌 목록에서 빠집니다.
- `index.lock`, `HEAD.lock`, `config.lock`, `packed-refs.lock`, `shallow.lock`을 표시합니다. linked worktree의 Git 디렉터리와 공통 디렉터리를 함께 확인합니다. 잠금을 자동 삭제하지 않습니다.
- **상태 다시 확인**은 로컬 상태를 재조회합니다. 외부 편집기나 Git 도구를 사용한 뒤에도 누릅니다.

진행 중인 작업·충돌·잠금이 있으면 일반 커밋, 브랜치 조작, 동기화를 제한합니다. GitClient도 전환·커밋·Reset·Merge·Rebase·Revert·Cherry-pick·Pull·Push 등의 실행 직전에 상태를 다시 검사하므로, 화면을 연 후 외부에서 상태가 바뀌어도 보호합니다. 충돌을 해결하기 위한 Stage/Unstage와 읽기 조회는 사용할 수 있으며, 실제 잠금 충돌은 Git이 추가로 검사합니다.

## 실행 중 표시와 중단

하단 상태 표시줄은 표시하지 않습니다. 상단 새로고침·동기화 버튼 오른쪽의 **현재작업 중단**으로 중단 가능한 작업을 멈춥니다. 명령·경과 시간·Git 진행 메시지는 작업 상태 탭에서, 실행한 명령은 작업 로그에서 확인합니다. Clone·원격 설정·작성자 설정창에도 중단 컨트롤이 있습니다.

| 작업 종류 | 사용자 중단 | 시간 제한 도달 |
|---|---|---|
| 읽기 조회 | 가능 | 프로세스를 중단하고 오류를 표시 |
| Fetch·Clone | 가능 | 중단 후 부분 결과와 잠금을 확인하도록 안내 |
| 커밋·Stage·Push·Pull·설정 쓰기·병합·복구 등 | 비활성화 | 시간 초과를 표시하고 명령 종료를 기다림 |

시간 제한은 **명령별 시간 제한 (초)**에서 1~7200초로 정하며 기본값은 120초입니다. 다음 Git 프로세스부터 적용하고 앱 재실행 후에도 유지합니다. 여러 명령으로 구성된 전체 작업의 누적 제한은 아닙니다.

쓰기 작업은 파일·Index·서버의 변경 중간을 강제로 끊지 않는 정책입니다. 시간 초과는 자동 롤백이나 강제 종료를 뜻하지 않습니다. 오랫동안 끝나지 않으면 표시된 인증 창·네트워크·Git hook 등 원인을 확인해야 합니다. 프로세스 실행 중에는 앱이나 해당 대화상자를 닫지 않습니다.

Windows에서는 시작을 잠시 보류한 Git 프로세스를 전용 Job Object에 연결한 후 실행합니다. 중단할 때 해당 작업의 하위 프로세스도 종료합니다. 프로세스 묶음 연결에 실패하면 안전한 중단을 보장할 수 없어 중단을 비활성화합니다. Unix 프로세스 그룹 처리도 있지만 이번 검증은 Windows 기준입니다.

Git 출력에 인증 관련 문구가 있으면 인증 응답 확인을 안내합니다. 15초 동안 출력이 없으면 네트워크·인증 창·hook 확인을 안내하며, 출력이 없다는 이유만으로 인증 대기라고 단정하지 않습니다. 앱 내부 로그인 화면은 추가하지 않습니다.

## 중단·실패 후

중단은 되돌리기가 아닙니다. Fetch로 일부 추적 참조가 갱신되거나 Clone 파일이 일부 생성되었을 수 있습니다. Push 오류도 서버가 전혀 바뀌지 않았다는 보장은 아닙니다.

변경 가능한 명령이 실패하거나 Fetch/Clone을 중단하면 동기화를 Fetch부터 다시 시작하도록 초기화하고 활성 저장소 상태를 재조회합니다. 실패한 Clone 디렉터리는 자동 삭제하지 않습니다. 중단한 읽기 조회는 자동 재시작하지 않아 같은 조회의 반복 실패를 막습니다.

최근 진단에는 명령, 종료 코드, 경과 시간, 결과와 변경 가능성 안내를 남깁니다. 비밀번호를 포함한 HTTP(S) URL의 사용자 정보와 기존 설정/커밋 입력 값은 명령 로그에서 가립니다. 이것은 모든 비밀 문자열을 탐지하는 완전한 로그 필터는 아닙니다.

조회 stdout은 수신하면서 제한합니다(기존 Diff·History 8 MiB, 일반 명령 기본 32 MiB). stderr는 최근 256 KiB를 보관합니다. 조회 출력 제한을 넘기면 중단하며 쓰기 명령은 출력 제한 때문에 강제로 종료하지 않습니다.

## Continue와 Abort

Merge, Rebase, Cherry-pick, Revert, AM의 **계속 · Continue**와 **진행 작업 취소 · Abort**를 제공합니다. bisect와 종류를 판별하지 못한 sequencer는 상태만 표시하며 외부 Git 도구로 처리합니다.

1. **병합 · 충돌 해결** 탭의 3-way 편집기에서 해결 결과를 저장·Stage합니다. 외부 편집기로 해결 후 Stage할 수도 있습니다. [편집기 안내](ADVANCED_COMMIT_AND_MERGE.md)를 참고하세요.
2. **Continue**는 충돌과 잠금이 없을 때 활성화됩니다. 기존 메시지를 사용하며 별도 커밋 메시지 편집기를 열지 않습니다. Rebase가 다음 충돌이나 편집 지점에 멈추면 새 상태를 표시합니다.
3. **Abort**는 Git이 제공하는 해당 작업의 `--abort`를 사용합니다. 충돌 해결 중인 수정이 사라질 수 있어 확인창을 거칩니다.
4. 확인 이후 작업 표시·Index·HEAD 등이 바뀌면 실행을 거부하고 새 상태를 확인하도록 합니다.
5. 실행 전 HEAD를 `refs/gitcanvas/recovery/<고유 ID>`에 보존합니다. 참조를 만들지 못하면 복구 명령을 실행하지 않습니다. 실행 후 상태를 다시 조회합니다.

복구 참조는 커밋을 보존하는 수단이며 미커밋 파일 전체의 백업이 아닙니다. **이력 수정 · 복구** 탭에서 reflog와 복구 참조를 탐색하고 새 브랜치 보존·현재 브랜치 되돌리기를 실행할 수 있습니다. 임의 작업의 자동 Undo는 후속 기능입니다. [이력 복구 안내](HISTORY_REWRITE_AND_RECOVERY.md)를 참고하세요.

HEAD가 아직 없는 첫 커밋 이전 작업처럼 복구 참조를 만들 수 없는 경우에는 외부 Git 도구로 처리해야 합니다.

## 검증 범위

임시 저장소에서 실제 Merge/Rebase/Cherry-pick/Revert 충돌을 만들고 상태 감지, 일반 커밋 차단, 해결 후 Continue, Merge Abort, 오래된 확인 상태 거부, HEAD 복구 참조, 잠금 보존·전환 차단을 검사합니다. Windows 테스트용 프로세스로 부모·자식 동시 중단, 읽기 시간 초과, 쓰기 시간 초과 시 계속 대기, 콜백 1회 완료도 검사합니다.

실제 인증 공급자의 모든 창, Git hook의 모든 동작, 모든 worktree/AM/bisect 조합과 네트워크 실패를 검증한 것은 아닙니다.
