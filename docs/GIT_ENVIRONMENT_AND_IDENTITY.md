# Git 환경과 작성자 설정

작업 순서 1번 구현 안내입니다. Workspace 아래의 **Git 환경 · 작성자 설정** 버튼에서 엽니다. 저장소를 열지 않아도 Git 진단과 전역 설정을 사용할 수 있습니다.

## Git 설치와 실행 확인

화면 위에 `git --version`의 결과, PATH에서 찾은 Git 실행 파일 경로, 현재 조회 대상 저장소를 표시합니다. **다시 확인**은 환경과 설정을 다시 읽습니다. 저장하지 않은 입력은 다시 읽은 값으로 바뀝니다.

Git을 실행할 수 없으면 작성자 저장을 비활성화하고 설치·PATH 확인 방법을 안내합니다. Windows에서는 Git for Windows를 설치하고 Git 명령을 PATH에서 사용할 수 있도록 선택한 뒤 GitCanvas를 다시 실행합니다. 앱이 Git을 자동 설치하거나 시스템 PATH를 수정하지는 않습니다. ZIP에는 Qt 실행 환경이 포함되며 Git은 별도 준비가 필요합니다.

## 이름과 이메일 저장

1. **저장 범위**를 선택합니다. 저장소가 열려 있으면 기본은 **이 저장소만 · Local**입니다. 저장소가 없으면 **현재 사용자 기본값 · Global**만 선택할 수 있습니다.
2. 새 커밋에 표시할 **이름**과 **이메일**을 입력합니다. 이름은 필수이며 제어 문자와 꺾쇠를 허용하지 않습니다. 이메일은 공백 없는 `name@example.com` 형태를 검사합니다. 실제 메일 수신 여부나 GitHub 계정 소유권을 검증하지는 않습니다.
3. **작성자 설정 저장**을 누릅니다. 선택한 범위의 `user.name`, `user.email`을 저장한 뒤 유효한 설정과 실제 커밋 신원을 다시 조회합니다.

Local은 이 저장소의 설정을 바꾸며 다른 저장소에는 영향을 주지 않습니다. Global은 현재 OS 사용자의 기본값을 바꾸므로 별도 작성자 설정이 없는 다른 저장소에도 적용됩니다. Windows 사용자 계정 이름을 변경하는 기능은 아닙니다.

입력 칸에는 선택한 범위에서 읽은 값이 표시됩니다. 해당 범위에 값이 없으면 입력은 비어 있어도 다른 범위에서 상속한 신원을 사용할 수 있습니다. 설정 삭제, Local 해제 후 Global 상속 복원, system/worktree 범위 편집은 이번 화면의 범위에 포함되지 않습니다.

## 실제로 사용되는 작성자 확인

읽기 전용 영역은 현재 유효한 `user.name`·`user.email`과 각각의 범위·설정 파일 출처를 표시합니다. 조건부 include와 worktree 설정은 Git이 판단한 결과를 반영합니다.

추가로 `git var GIT_AUTHOR_IDENT`, `git var GIT_COMMITTER_IDENT`를 조회해 **실제 작성자**와 **실제 기록자**를 보여줍니다. `GIT_AUTHOR_*`, `GIT_COMMITTER_*` 같은 환경 변수가 있으면 저장한 설정보다 우선할 수 있습니다. Git의 기본 신원 추론도 이 결과에 반영됩니다. 따라서 Global에 저장했다고 항상 그 값으로 커밋되는 것은 아닙니다.

작성자 설정은 GitHub 로그인이나 원격 저장소 인증과 별개이며, 기존 커밋의 작성자를 바꾸지 않습니다. 환경 변수 자체를 편집하는 기능도 아닙니다.

## 커밋할 때의 동작과 오류

**커밋 만들기**는 실행 전에 작성자와 기록자 신원을 확인합니다. 확인이 실패하면 설정 화면을 열며 제목·상세 설명·Staged 파일을 유지합니다. 설정을 저장하고 닫은 다음 **커밋 만들기**를 다시 누릅니다. 설정 저장만으로 자동 커밋하지 않습니다.

이름과 이메일은 각각 Git의 설정 파일 잠금을 통해 순서대로 저장합니다. 이름 저장 실패 시 이메일을 변경하지 않습니다. 이름 저장 후 이메일이 실패하면 부분 저장 상태를 명시하고 현재 유효한 값을 다시 보여줍니다. 두 값 전체를 하나의 트랜잭션으로 저장하는 방식은 아닙니다.

Git 실행 중에는 설정 편집과 창 닫기를 제한합니다. 입력한 이름과 이메일은 설정 쓰기 명령의 작업 로그에서 `<value>`로 가립니다.

## 검증

임시 전역 설정 파일과 임시 저장소를 사용하는 테스트로 다음을 확인합니다. 개발자의 실제 전역 설정은 변경하지 않습니다.

- 저장소 없는 상태의 Git 버전 진단과 첫 전역 설정 생성
- 입력 검증, Local/Global 저장 범위 분리, 실제 커밋 작성자 반영
- 저장소 설정 우선순위, 환경 변수의 실제 신원 반영
- 설정 파일 잠금 실패 시 원래 값 보존, 설정 쓰기 로그 값 가림
- Git 실행 파일이 없을 때 안내 및 저장 비활성화
- 신원이 없는 첫 커밋에서 설정 화면 진입, 초안 유지, 설정 후 GUI 커밋 성공
