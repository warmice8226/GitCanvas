# GitHub Pull Request 협업

작업 순서 10의 기본 PR 협업 기능입니다. Windows 무설치 배포본의 GitHub 로그인과 같은 gh 계정을 사용합니다.

## 열기

1. **GitHub** 탭에서 로그인합니다.
2. 저장소 목록에서 대상 저장소를 선택하고 **Pull Requests**를 누릅니다.
3. 제목표시줄 없는 큰 창에서 PR 목록과 상세를 함께 확인합니다. 로컬 폴더를 열지 않아도 조회·작성·리뷰·병합을 사용할 수 있습니다.

목록은 열린 PR, 닫힌 PR, 전체, 병합된 PR, 초안으로 구분합니다. 100개씩 이어 읽고 불러온 제목·번호·작성자·브랜치·요청한 리뷰어·라벨을 검색합니다. 병합/초안 필터는 서버의 closed/open 목록 중 해당 항목만 표시하므로 현재 페이지에 없으면 다음 페이지를 읽으세요.

## 상세와 변경 파일

선택한 PR의 제목·본문·head/base·SHA·병합 상태·커밋·댓글·리뷰·요청한 리뷰어·CI를 표시합니다. 아래 왼쪽에서 변경 파일을 선택하면 오른쪽의 기존 Diff 화면으로 확인합니다. 통합·나란히·쌓기형 비교를 제공하며 줄 선택과 Stage 기능은 없습니다. 코드 리뷰 댓글의 파일과 줄 위치도 읽습니다.

**상세·CI 다시 읽기**는 관련 페이지를 모두 다시 읽습니다. 파일·댓글·리뷰·커밋·Check Run은 100개씩 최대 30페이지이며, 항목별 누적 16 MiB를 넘거나 전체 조회를 확인하지 못하면 쓰기를 비활성화합니다. 개별 응답은 기존 4 MiB 제한을 적용합니다. GitHub API 자체의 파일·커밋 제한과 생략된 patch도 있으므로 큰 PR·바이너리는 **GitHub에서 열기** 또는 로컬 체크아웃으로 확인하세요.

## PR 생성

**PR 만들기**에서 합류할 base와 변경 사항이 있는 head를 드롭다운으로 선택합니다. 기본 head 저장소는 선택한 저장소이며, fork는 **변경 브랜치 저장소**에 `소유자/저장소`를 입력하고 브랜치를 다시 읽습니다.

- 제목·설명·초안 여부를 입력하고 최종 확인 후 생성합니다.
- **커밋·Diff 미리보기**로 원격 base/head를 비교합니다. 처음 100개 커밋과 API가 제공한 최대 300개 파일을 표시합니다.
- **템플릿 읽기**로 선택한 저장소의 기본 브랜치에서 일반적인 PR 템플릿 경로를 읽습니다. 기존 설명을 바꾸기 전에 확인합니다.
- 생성 전에 원격 브랜치 존재 여부와 동일한 head/base의 열린 PR을 확인합니다. 요청 결과가 불확실할 때 자동으로 POST를 반복하지 않습니다.
- 생성된 PR 번호를 상세에 표시하며 **GitHub에서 열기**로 이동할 수 있습니다.

생성 대상은 이미 GitHub에 게시된 브랜치입니다. 로컬의 미게시 커밋을 자동으로 올리지는 않으며, 기존 Fetch/Push 흐름으로 먼저 게시하세요. fork의 저장소 관계와 사용자 권한은 서버가 최종 검증합니다.

## 댓글과 리뷰

아래 작업 선택에서 내용을 입력하고 **GitHub에 보내기**를 누릅니다. 확인 창에는 호스트·계정·저장소·PR·브랜치·확인한 커밋과 보낼 내용을 표시합니다.

- 일반 댓글, 승인, 변경 요청 리뷰
- 사용자·팀 리뷰 요청 및 요청 취소: `alice, bob, team:reviewers` 형식
- **초안 → 리뷰 준비**
- **Base 변경 사항으로 PR 갱신**: 서버에서 base를 PR 브랜치에 병합하도록 요청하며 `expected_head_sha`로 확인한 커밋을 지정합니다.
- **PR 닫기 / PR 다시 열기**: 병합된 PR은 재열지 않습니다.

자신이 작성한 PR에는 승인/변경 요청을 보내지 않습니다. 승인·변경 요청에는 리뷰한 `commit_id`를 전송합니다. 댓글과 리뷰 본문은 JSON 표준입력으로 전달하며 명령 로그에 포함하지 않습니다.

## 병합

Merge 커밋, Squash, Rebase 중 저장소에서 허용한 방식을 사용합니다. 로컬 Git 병합과는 별개로 GitHub의 PR을 병합하는 작업입니다.

앱은 쓰기 권한, 열린 상태, 초안 아님, `mergeable=true`, `mergeable_state=clean`, 모든 조회된 Check Run 완료 및 성공/중립/생략, combined commit status 성공을 확인합니다. 필수가 아닌 검사도 실패·대기 중이면 보수적으로 병합을 막습니다. CI가 하나도 없는 저장소는 서버의 clean 상태와 권한을 확인합니다. 필수 리뷰·브랜치 보호 조건이 충족되지 않아 blocked/unknown인 경우에도 병합하지 않습니다.

실행 직전에 PR과 검사 상태를 다시 읽고 head/base SHA·상태·갱신 시각이 확인한 값과 같은지 비교합니다. 병합 API에는 head `sha`를 보내며 서버 응답의 `merged=true`까지 확인합니다. 관리자 우회나 강제 병합은 제공하지 않습니다. 서버 규칙과 허용된 병합 방식이 최종적으로 적용됩니다.

## 로컬에서 열기

선택한 GitHub 저장소에 해당하는 로컬 폴더를 먼저 열고 **로컬에서 열기**를 누릅니다. 원격 URL이 일치하는지 검사하고, 미커밋·미추적 변경이 있으면 먼저 커밋/Stash하도록 안내합니다.

`refs/pull/번호/head`를 `pr/번호-SHA앞12자` 로컬 브랜치로 Fetch한 뒤 확인한 SHA와 비교하고 전환합니다. Fetch 후 변경 사항을 다시 검사하며 무시 파일은 `--no-overwrite-ignore`로 보호합니다. 기존 브랜치를 강제로 덮어쓰지 않습니다. 실패하거나 중단한 경우 가져온 로컬 PR 브랜치는 남을 수 있습니다. 원격 브랜치는 삭제하지 않습니다.

## 오류·중단과 현재 범위

GitHub 요청은 비동기로 실행하며 **요청 중단**을 제공합니다. 진행 중 창을 닫지 못하게 하고, 계정 변경이나 다른 Git 작업이 겹치지 않게 공통 작업 잠금과 연결합니다. Git 쓰기의 마지막 전환 단계처럼 즉시 중단할 수 없는 단계는 완료를 기다립니다.

각 요청 전에 활성 계정을 재검증하고 조회 후에도 다시 확인합니다. 인증·권한·SSO·호출 한도·409/405 상태 변경·422 입력/작업 조건 오류를 안내합니다. 이미 전송한 원격 쓰기는 취소로 되돌릴 수 없으므로 실패·중단 후에는 목록/상세를 읽고 결과를 확인하세요. 계정 전환과 원격 API 요청을 다른 앱과 원자적으로 잠그지는 못합니다. 댓글·닫기 등 서버에 SHA 조건이 없는 요청에는 마지막 재검증과 쓰기 사이의 경합 가능성이 남습니다.

후속 고급 범위: 작성 중 reviewer/assignee/label/milestone/project 일괄 지정, 여러 템플릿 탐색, 미게시 커밋 Push 연결, 코드 줄별 댓글 작성·discussion 해결, 병합 후 원격 브랜치 정리, 보호 규칙의 개별 조건 설명·merge queue/auto-merge. 이 항목은 기본 PR 협업 구현과 구분합니다.

## 검증

모의 gh/API로 페이지 조회, 생성 본문·초안·중복 PR, fork 브랜치 비교·템플릿, 댓글·승인·변경 요청·리뷰어 요청/취소·리뷰 준비·브랜치 갱신·닫기/재열기·병합, SHA 변경·검사 실패/대기·blocked·계정 변경·서버의 병합 거부·중단을 검사합니다. 임시 실제 Git 저장소로 로컬 PR Fetch/전환과 미커밋·무시 파일 보호를 검증합니다. GUI 진입과 생성 창, 읽기 전용 Diff도 검사합니다. 실제 GitHub 계정으로 PR을 만들거나 리뷰·병합하지는 않았으며, Enterprise·조직 SSO·세부 보호 규칙의 실서버 검증은 별도입니다.

공식 API: [PR 조회·생성·갱신·병합](https://docs.github.com/en/rest/pulls/pulls), [리뷰](https://docs.github.com/en/rest/pulls/reviews), [리뷰 요청](https://docs.github.com/en/rest/pulls/review-requests), [브랜치 비교](https://docs.github.com/en/rest/commits/commits#compare-two-commits).
