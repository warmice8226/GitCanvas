# 고급 커밋·줄 선택 Diff·병합과 3-way 충돌 해결

작업 순서 6·7의 Windows 프로토타입 안내입니다.

## 커밋 옵션

**마지막 커밋 수정 · Amend**는 마지막 커밋을 현재 Stage 전체와 입력한 메시지로 교체합니다. 입력칸이 비어 있으면 기존 메시지를 가져오고, 작성 중인 초안은 유지합니다. Stage 변경 없이 메시지만 수정할 수도 있습니다. 기존 작성자와 부모 관계는 유지되며 커밋 ID가 바뀝니다.

실행할 때 이력 변경을 확인하고, 선택 이후 HEAD가 바뀌면 거부합니다. 원래 커밋은 `refs/gitcanvas/amend-backups/<ID>`에 보존합니다. 공유한 커밋을 수정하면 원격과 이력이 갈라질 수 있습니다. 자동 강제 Push는 제공하지 않습니다.

**Signed-off-by 추가**는 Git의 `--signoff`로 현재 커미터의 이름·이메일을 메시지에 추가합니다. 프로젝트의 기여 확인 규칙에 맞춰 선택하세요. GPG/SSH 암호학적 서명 기능은 아닙니다.

## 줄 단위 Stage / Unstage

1. 파일을 클릭한 뒤 Diff 보기 목록에서 **줄 선택**을 선택합니다.
2. 반영할 `+` 추가 줄과 `-` 삭제 줄을 체크합니다. 교체는 삭제와 추가를 각각 체크하며 문맥 줄은 체크하지 않습니다.
3. **체크한 줄 Stage**로 선택 변경만 인덱스에 넣습니다. 커밋할 파일 목록에서는 **체크한 줄 Unstage**로 선택 변경만 뺍니다.

작업 파일은 변경하지 않습니다. 신규·삭제 텍스트 파일도 줄 선택을 지원하며, 새 파일 조회를 위해 intent-to-add나 Stage를 미리 실행하지 않습니다. 신규·삭제 파일에서는 구간 버튼 대신 줄 선택 또는 파일 전체 작업을 사용합니다.

패치의 원래 바이트를 유지하면서 선택에 맞춰 문맥·줄 수를 다시 계산합니다. Unstage는 Index 기준의 역방향 패치를 만듭니다. 원본 Diff 재검사와 `git apply --cached --check` 후 적용하며 유효하지 않은 선택은 Git 오류로 거부합니다.

부분 적용은 UTF-8 일반 텍스트, Diff 최대 8 MiB·2만 줄 범위입니다. 바이너리, 비 UTF-8, 심볼릭 링크·서브모듈, 파일 모드 변경은 파일 단위로 처리합니다. 대형 파일 가상화는 후속 범위입니다.

## 비교와 병합

**병합 · 충돌 해결 → 브랜치 비교 · 병합**의 드롭다운에서 기존 로컬·원격 추적 브랜치를 선택합니다. 직접 입력은 제공하지 않습니다. 비교 화면은 각 쪽에만 있는 커밋(최대 100개), 파일 통계와 패치를 보여줍니다. 원격 추적 브랜치는 마지막 Fetch의 로컬 사본이므로 최신 원격 상태는 상단 Fetch로 갱신하세요.

**비교한 커밋 병합**은 영향 확인 후 대상 OID·HEAD·인덱스·작업 상태를 재검사합니다. 로컬 브랜치에 있어야 하며 미추적 파일을 포함한 작업 변경, 진행 작업, 잠금이 있으면 차단합니다. 병합 전 HEAD는 `refs/gitcanvas/merge-backups/<ID>`에 남깁니다.

가능하면 fast-forward하고, 이력이 갈라졌으면 일반 병합을 실행합니다. 자동 Stash/Rebase와 무시된 파일 덮어쓰기는 허용하지 않습니다. 충돌 시 병합 상태를 유지하고 같은 화면의 충돌 파일 구역으로 이동합니다.

상단 동기화 버튼도 Fetch 후 양쪽 이력이 갈라지면 **Pull 우선 · 이력 통합 필요** 상태에서 비교 화면을 엽니다. 확인한 upstream을 병합하고 필요한 충돌을 해결한 뒤 다시 Fetch하면 Push로 이어갈 수 있습니다. 자동 Push나 강제 Push는 하지 않습니다.

## 3-way 편집기

충돌 파일을 선택하거나 **선택 파일 충돌 편집**을 누르면 제목표시줄 없는 큰 창이 열립니다. **왼쪽 Base branch(병합을 받는 현재 쪽, stage 2)**, **가운데 최종 결과(편집 가능)**, **오른쪽 Merge branch(합칠 쪽, stage 3)** 순서로 표시합니다. 공통 조상인 stage 1은 백업에 보관하며 화면의 Base와 구분합니다. 파일이 없는 삭제/수정 충돌도 표현합니다.

- 결과를 직접 편집하고 **결과 저장 + Stage**를 누릅니다. 충돌 표시가 남아 있으면 저장을 거부합니다.
- 전체 처리 선택지는 **Base 파일 사용**, **Merge 파일 사용**, **해당 파일 삭제** 세 가지입니다. 선택한 버전 전체를 저장하거나 삭제한 뒤 해당 파일을 Stage하며 먼저 확인창을 표시합니다. 선택한 쪽에 파일이 없으면 삭제로 해결합니다.
- 저장 성공 시 편집창을 닫고 파일 목록을 갱신합니다. 저장 실패는 편집창 안에도 표시하며 편집 내용을 유지합니다. 저장하지 않은 내용을 버리고 닫으려면 확인해야 합니다.

Ours/Theirs는 Git stage 2/3을 뜻합니다. **Rebase의 Ours는 재배치 기준 쪽, Theirs는 지금 재적용하는 커밋**이므로 ‘내 코드=Ours’로 해석하면 안 됩니다. 화면에서도 구분을 안내합니다.

UTF-8 일반 파일은 직접 편집하며 현재 작업 파일의 CRLF와 UTF-8 BOM을 보존합니다. 바이너리·비 UTF-8은 변환하지 않고 전체 버전 선택/삭제만 제공합니다. 각 버전과 결과는 최대 8 MiB입니다. 심볼릭 링크·서브모듈, 서로 다른 실행 권한의 모드 충돌, 디렉터리와 복잡한 경로 충돌은 외부 도구로 처리합니다. 기본과 다른 충돌 표시는 직접 편집하세요.

## 저장·계속·복구

읽은 뒤 파일·인덱스·작업 상태가 바뀌면 저장하지 않습니다. 실행 전 실제 Git 디렉터리의 `gitcanvas/conflict-backups/<ID>/`에 원본을 보관합니다.

- `working.bin`: 해결 전 작업 파일
- `1.bin`, `2.bin`, `3.bin`: 존재하는 공통 조상/Ours/Theirs 버전(화면의 Base는 `2.bin`, Merge는 `3.bin`)
- `manifest.json`: 저장소, 상대 경로, 원래 파일 존재 여부

백업 실패 시 원본을 유지하고 백업 후에도 상태와 파일을 재검사합니다. QSaveFile로 저장한 뒤 해당 경로만 Stage합니다. Stage 실패 시 파일은 이미 저장/삭제되었을 수 있으므로 결과 메시지의 백업 위치를 확인하세요. 외부 프로그램의 동시 쓰기를 완전히 잠그지는 않습니다.

충돌이 모두 해결되면 **Continue**로 Merge/Rebase/Cherry-pick/Revert/AM을 이어갑니다. 다른 Stage 파일도 포함될 수 있으므로 변경 사항 탭을 확인하세요. 다음 충돌이 생기면 목록을 갱신합니다. **Abort**는 Git의 작업 취소이며 해결 중인 변경이 사라질 수 있으나 파일별 백업은 유지됩니다. Stash 충돌은 전용 Continue/Abort가 없으며 해결 후 일반 커밋으로 진행합니다.

저장하지 않은 편집을 다시 읽거나 저장소를 바꾸거나 창을 닫을 때는 버릴지 확인합니다. [이력 수정·복구 탭](HISTORY_REWRITE_AND_RECOVERY.md)에서 커밋 복구 참조를 탐색·복구하고 백업 폴더를 열 수 있습니다. 파일 백업은 manifest의 경로를 확인해 수동으로 복사합니다.

## 검증

임시 저장소에서 Amend 작성자·부모 유지, sign-off·오래된 HEAD 거부, 일반/신규/삭제 파일의 선택 줄 적용, 병합 충돌·3개 버전 조회·오래된 해결 거부·백업·별도 GUI 편집창·닫기 보호·저장/Continue, 삭제/수정 충돌, Fetch 후 비교·병합·재Fetch·Push를 검사합니다. 기존 Diff/History와 공통 복구 테스트도 함께 실행합니다. 실제 호스팅 인증, 모든 충돌 조합, 대규모 저장소와 Linux/macOS 실행은 별도 검증 대상입니다.
